# V102 source and provenance audit

Run `python3 scripts/cu66-v102/audit_sources.py` to regenerate the deterministic standard-library audit at `experiments/python-gamebub-v102/source-audit.json`. The audit pins baseline commit `6b36a3228804953c50c10db61f620cad5412ecce`, verifies that it exists and is an ancestor of the current checkout, checks the frozen V99 research profile against its SHA and baseline Git blob, and compares the complete V100 RTL source inventory to both its recorded hashes and the baseline blobs.

The memory candidate is reconstructed byte-for-byte from its baseline admission source by applying only the approved read-template transformation: a prioritized read enable/address mux and a single registered packet-memory read, with the `ram_data` assignments removed from the metadata process. Its original and candidate hashes, manifest, and public module header are checked.

The predicate candidate is constrained to the `safe_hidden` function body. Its baseline source hash, candidate hash, unchanged-prefix/suffix pins, public module header, manifest schema and baseline revision are checked. No counter, clocked process, or state logic is within that approved span.

The source audit also verifies focused RTL receipts and all artifacts they declare. The predicate actual-RTL Verilator run passes all 32,768 combinations across the full two-bit plane and thirteen-bit tile domain, with zero clock edges, strict warnings, unchanged 72 production ports, and an independent Cartesian-set replay of every trace tuple. This is exhaustive combinational predicate coverage; it does not cover sequential protocol behavior.

The packet-memory focused Verilator receipt passes for seeds `102401` and `102402`: 9,536 cases and 9,537 clock edges per seed, 32 forced read-first collision cases per seed, and 19,072 cases / 19,074 edges total. Both variants compare all public outputs and RAM response metadata; the run also checks an independent RAM byte oracle and all 49,152 final memory bytes. The verification-only force controls reach collisions that the normal FSM excludes; the receipt limits explicitly do not count this as a complete packet-admission protocol test.

The audit checks the selected paired fresh memory regression and the memory, predicate, and combined canonical regressions. Fresh memory mode has two seeds, six cases and 13 directed checks per seed and variant, 24 case/profile runs and 52 directed checks total. Each canonical lane has two seeds, 22 cases and 21 directed checks per seed and variant, 88 case/profile runs and 84 directed checks total. Receipts require exact transcript/event equality; canonical receipts also require canonical-byte equality. The audit checks source pins, successful terminal verdicts, and all declared artifact hashes.

The current source audit reports `PASS_EVIDENCE` for 17/17 checks. It binds both focused receipts and all four paired regressions to their selected reports and SHA-256 verifies every declared attempt artifact. A passing source/receipt audit does not establish full system behavioral equivalence or any synthesis, capacity, placement, timing, or physical result. Root owns vendor builds and the separate vendor capacity/timing verification.
