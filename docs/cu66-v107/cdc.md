# V107 clock, reset and crossing experiment

**Behavioral channel fabric PASS; board/complete-parent integration remains open.** The selected V106 decoder is an out-of-context `cs88_pipeline_v91k`, while the checked-in board top instantiates the legacy JPEG `moonshine_core`. Connecting those designs requires protocol, memory-format and presentation adapters; their existence cannot be inferred from matching clock names. This experiment changes no production RTL and makes no board-clock, interface-timing, metastability, CDC-signoff or hardware claim.

The [fabric RTL](../../fpga/experiments/cu66-v107-cdc/v107_cdc_fabric.sv), [async FIFO](../../fpga/experiments/cu66-v107-cdc/v107_async_fifo.sv) and [reset release](../../fpga/experiments/cu66-v107-cdc/v107_reset_release.sv) implement five independent finite channels and a common reset contract. They accept four explicit clock inputs; simulation frequencies are test stimulus. [Results](../../experiments/python-gamebub-v107/cdc/results.json) select the passing receipt, with immutable source snapshots, strict compile transcript, executable hash and compressed transfer traces. The [source inventory](../../experiments/python-gamebub-v107/cdc/inventory.json) hashes actual source files inspected for this review.

## Implemented experimental interface

Each channel transfers its entire payload atomically under valid/ready. The Gray pointers and two-stage pointer synchronizers move ownership; the dual-clock RAM moves payload. A registered synchronous RAM read holds output stable under stalls. RAM depth is eight, with one additional output holding slot; full and empty decisions include synchronization delay. Ready is gated until the peer has completed reset release and its up token has crossed. No memory contents need clearing.

| Channel | Direction | Bits / source-matched packing | Adapter still required |
| --- | --- | --- | --- |
| `commands` | transport -> decoder | 44: `{address[11:0],wdata[31:0]}`, existing bus bridge tuple | Actual QSPI endpoint only pulses writes. It cannot stall on this candidate ready pin; use finite credit/loss reporting and atomic abort/retry. Read mailbox and status/credit return are absent here. |
| `writes` | decoder -> memory | 94: `{req_epoch[31:0],req_token[31:0],req_bank[1:0],req_addr[19:0],req_data[7:0]}` from CU66 write/hash join | Instantiate actual join and byte-to-physical-memory arbiter, preserving acknowledgement after physical commitment. |
| `acks` | memory -> decoder | 87: `{rsp_epoch[31:0],rsp_token[31:0],rsp_bank[1:0],rsp_addr[19:0],rsp_error}` from same join | Preserve owner/epoch/token checks and stale-response rejection at the join; FIFO does not interpret tags. |
| `lines` | display -> memory | 24: existing `moonshine_lcd.line_req_address` | Existing LCD request port is in memory domain already. Moving the transaction to display domain requires a reviewed line ownership/epoch adapter, not a direct port substitution. |
| `pixels` | memory -> display | 16: existing RGB565 line data word | Actual SDRAM returns an unstallable burst and LCD line banks provide buffering. This candidate ready interface requires a whole-burst credit reservation/buffer; eight FIFO words plus one slot cannot promise a 480-word line. |

`commands/lines/pixels` have no explicit transaction epoch field in their source interfaces. The testbench uses reset epochs to prove no queued pre-reset word is delivered afterward. The write/ack payload preserves all real tag bits without decoding them. This is channel bit/order coverage, not proof of valid CU66 packets, physical acknowledgements, full-frame rendering, reference leases or stale responses newly emitted by an external owner after reset.

## Reset / abort contract

All four `reset_request` bits are requests for **one coordinated asynchronous reset**. Any asserted bit resets every channel side immediately; each domain releases through its own three local clock edges. A stopped domain holds reset until it clocks again, and peers cannot send to it until its up token crosses. Independent one-sided FIFO reset is unsupported and impossible through the fabric's external reset interface. Reset discards all accepted but undelivered channel words.

The physical controller, decoder transaction owners, transport accounting and display bank ownership must participate in this same reset/restart contract before this fabric is used in a parent. A fabric flush cannot undo an SDRAM write already committed, retire an in-flight physical burst, or reject stale traffic newly emitted by an owner after reset. Reset is an abort fence only when all owners either reset/drain or keep rejecting old epoch/generation responses. Reset pulses must reach all local async reset pins and satisfy device minimum pulse requirements. The common OR requires clean, glitch-free reset request sources. Behavioral simulation cannot prove reset distribution or metastability MTBF.

## Executed evidence and remaining constraints

Verilator 5.020, behavioral two-state, `--assert -Wall`, no Verilator warning suppression, C++ `-Wall -Wextra -Werror`, two build jobs, bounded compile/run timeouts. Seeds 107001/107002/107003 each ran 120,000 ticks and 45,809 total rising edges across four clocks. Half-periods 3/5/7/11 ticks, staggered first clocks, independently stopped/restarted clocks, long deterministic and randomized stalls, pointer wrap, full/empty traffic, and six reset epochs include each individual reset-request source and reset while memory clock is stopped. Total: **74,060 accepted, 73,596 delivered, 464 explicitly discarded by reset**. Every accepted/delivered payload bit and order is checked by a C++ queue scoreboard; a separate Python trace replay independently checks the retained accepted/delivered/reset event stream. All five channels require exercised full backpressure, held output, delivered words and reset discards. Assertions check Gray single-bit changes and output stability. Assertions and scoreboards are not formal proof.

Two failed attempts remain retained: strict Verilator reset-use/SVA warnings, then strict C++ missing-field-initializer failure. The final design uses separate peer-up tokens and immediate clocked assertions, with no waived warning and no disabled checker. Those failures were compile/testbench issues, not functional PASS evidence.

Reproduce from the repository with `python3 scripts/cu66-v107/cdc.py`. Build products remain on the external `/build` mount; portable snapshots/traces/logs/receipts remain in the repository. A trace can be replayed without a simulator with `python3 scripts/cu66-v107/cdc.py --replay <seed.csv.gz>`.

The [historical constraints template](../../fpga/experiments/cu66-v107-cdc/constraints.tcl) is **rejected by actual native preflight** and retained unchanged for audit. The original exact source-name count misses Vivado's merged Gray MSB; raw Q startpoints also cause path segmentation and invalid false-path startpoints. Do not apply that template to a parent. The separate [native qualification study](cdc-native.md) preserves those failures and tests an exact mapped-driver repair using valid sequential C-pin startpoints to the same strict first-stage D endpoints. The repaired procedure validates every actual Gray bit source (including a binary MSB alias) and same-clock shared peer-up sources. It creates no clocks or broad clock groups. Parent reset recovery/removal and RAM recognition remain separate review obligations.

Use the actual source period (or a tighter bound) so successive Gray transitions cannot overtake one another at the receiver. An asynchronous clock group must not override these bounds. AMD's [asynchronous-signal constraints](https://docs.amd.com/r/en-US/ug903-vivado-using-constraints/Constraining-Asynchronous-Signals) and [bus-skew guidance](https://docs.amd.com/r/en-US/ug903-vivado-using-constraints/About-Bus-Skew-Constraints) explain the distinction; Gray max delay and bus skew require explicit coverage review. The historical template passed only a stubbed Tcl parse; actual mapped testing exposed its defects, illustrating why a syntax check cannot qualify constraints. Required mapped review includes RAM inference, synchronizer placement, report_cdc, exceptions coverage, bus skew, each Gray first-stage timing path and reset recovery/removal. A complete implementation must not false-path the phase-related SDRAM capture path.

## Concrete complete-parent closure sequence

1. Freeze the actual board source/constraints and the selected CU66 source map separately. Establish real oscillator/PLL, QSPI capture and SDRAM/LCD budgets. Preserve transport 200 MHz, memory/read phases and panel clock. Any alternative decoder clock is a separate named integration variant.
2. Build a real transport owner that converts the existing register/write protocol into CU66 packet-byte valid/ready/last plus stable `packet_bytes/epoch/start/abort`. Implement bounded ingress credits and loss detection, tagged status/credit return and reset fencing. Prove dropped commands invalidate a transaction; preserve firmware-facing ordering and read latency.
3. Instantiate the selected CU66 with actual frame-bank/reference/cache ownership. Cross all reference request/response fields atomically, including 64-bit generation and 512-bit tile payload. Join canonical/HUD writes to real physical write acknowledgements; map planar byte output into the actual SDRAM/display representation. Test refresh, finite arbitration and concurrent read/write traffic.
4. Preserve LCD two-bank ownership or implement a separately verified replacement. Reserve response capacity for every unstallable SDRAM burst; carry line/frame/bank ownership until completion. Blank stale lines after restart and prove neither writer nor display uses a retired bank. Include overlay and status-counter crossings.
5. Add the common reset/abort policy to every real owner. Replay reset during requests/acks/bursts/display reads, independently stopped/start clocks, transport overflow, delayed/wrong-epoch responses and post-abort restart. Re-run canonical pixel/HUD/hash/frame-fence checks with actual memory cost.
6. Apply narrowly matched constraints to the mapped **complete parent**; resolve CDC/methodology reports, setup/hold/pulse-width and all I/O paths. Retain report coverage and source/bitstream/firmware hashes. Hardware smoke/30-fps/validated-under-10-ms gates remain pending until measured on the board.
