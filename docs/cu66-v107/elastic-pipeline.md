# V107 elastic boundary: actual canonical pipeline qualification

This lane compares the complete quant-aligned control against the same source closure with the frozen coefficient stage and canonical top replacement. Both lanes include Rice alignment, quant run-byte prefetch, the exact inverse range predicate and all selected sixth-source overrides. The only architectural difference is the registered coefficient boundary.

The frozen canonical manifest has 16 RTL files and one quant-ROM include header: 17 closure files. The candidate adds one RTL module, yielding 17 RTL files plus the header: 18 closure files. The retained first preflight rejected an incorrect 17-RTL assumption before compiling; the corrected gate explicitly counts RTL and headers separately. No module is omitted or added merely to satisfy a numeric claim.

The verification bench is a copy of the historical canonical bench. It preserves every original golden/provenance/order/cancel/ownership/fault/publication check. Its exact [bench recipe](../../fpga/experiments/cu66-v107-elastic/verification/bench-edit-recipe.json) inventories all 129 original `need` calls, retained alongside 15 added checks. The candidate's former immediate inverse-input count equality is adapted to explicit accepted/upstream, accepted/downstream and flush-discard conservation; successful frames still require the original exact equality.

An independent one-entry tuple queue monitors raw upstream acceptance, staged downstream acceptance and actual flush edges. Every visible staged tuple must equal the complete 130-bit accepted owner; every edge checks registered occupancy, held payload, ordered done fence and the inverse input counter. A flush discards exactly the previously accepted queued owner; a blocked final input offer is not an accepted owner. Good completion requires no queued owners/discards and upstream=downstream=inverse_count_inputs. Error completion requires upstream=downstream+explicit discards, drained stage ownership, the original expected error and no successful publication. Directed reset/start/abort and physical scratch/reference ACK drain checks remain intact.

Each successful case/profile still checks all 8100 tiles and 518400 exact canonical samples against frozen independent goldens, plus every coefficient, assembled tile, dequantized value, residual and ownership/metadata tuple. Ordered semantic event streams are compared separately by case/profile/type/stage, removing only cycle/first_cycle/last_cycle fields. Canonical output byte files remain exactly equal across same-seed control/candidate. Incomplete error-frame prefixes retain all inline exact-golden/order/ownership checks; their cycle-dependent lengths are not declared equal. C2/HUD/full accepted-frame publication remains outside the historical bench's scope.

Both finite memory/reference profiles are retained. The receipt records every case's control/candidate cycles and behavioral latency at 100 MHz, as well as counters and frame epochs. Cycle equality is deliberately not an acceptance condition for the declared one-register architecture. Simulation latency under modeled service is not hardware throughput or complete-system decode qualification.

The backend is explicitly historical Verilator with `-Wall --assert --public-flat-rw` and C++ warnings as errors. No Verilator warning suppression is used. Private exposure is verification-only; the production stage/top bytes remain the unit-tested frozen sources. The repaired compile commands use one job plus documented Verilator output/function splitting, host 8 GiB available-memory and PSI launch gates, and finite compile/runtime/watchdog bounds. The second attempt retained an actual compiler OOM at the shared container 4 GiB cap despite host headroom. Root then independently raised the container to 8 GiB RAM with zero additional swap; the repaired attempt snapshots this capacity change and prior OOM counter in container-memory.json. The RTL, bench and functional gates were unchanged for this environment repair. Each attempt snapshots sources, inputs, bench, compiler commands/logs, binaries, semantic traces and actual pixel artifacts.
