# V107 status and telemetry pipeline inventory

Reviewed 2026-11-08 against the selected **PAYLOAD** and combined **THRESHOLD** source closures. A coherent delayed diagnostic snapshot is feasible as a **new, versioned interface proposal**. The existing live operational signals and public test contract remain unchanged. No snapshot RTL, telemetry retiming, new host bus, register map, CDC, timing exception or performance improvement is implemented or claimed here.

## Existing verification contract is stricter than eventual diagnostics

The full canonical bench uses live readiness for cache writes [345](../../fpga/experiments/cu66-v107-elastic/verification/bench.cpp#L345), start [354](../../fpga/experiments/cu66-v107-elastic/verification/bench.cpp#L354) and ownership drain [370](../../fpga/experiments/cu66-v107-elastic/verification/bench.cpp#L370). It records the first exact `done` and coefficient-done cycles [318](../../fpga/experiments/cu66-v107-elastic/verification/bench.cpp#L318), checks per-edge inverse accepted-input counts [143](../../fpga/experiments/cu66-v107-elastic/verification/bench.cpp#L143), and checks canonical/mode/reference/queue conservation totals [375](../../fpga/experiments/cu66-v107-elastic/verification/bench.cpp#L375). The selected proofs compare the same-seed stdout/events/canonical files byte-for-byte, including cycles [threshold runner:169](../../scripts/cu66-v107/threshold_pipeline.py#L169). They do not establish a relaxed diagnostic latency contract.

The four-body threshold focus additionally compares **all 167 original child public ports** including invalid payloads, live counters, timestamps, debug and unpacked arrays, before and after each tested edge: [complete comparison](../../fpga/experiments/cu66-v107-count-threshold/verification/prefix_probe.sv#L659), [bench check](../../fpga/experiments/cu66-v107-count-threshold/verification/tb_prefix.cpp#L969). The IDCT focus separately checks `active_cycles` each edge, resets, 0/4/128-cycle paths and stalled output stability: [IDCT oracle](../../fpga/experiments/cu66-v107-idct-reset/tb_idct.cpp#L31). No existing test is waived because a port is “only telemetry.” These focused checks and full canonical checks have different scopes; full canonical is not asserted to compare every top debug bit on every edge.

## Proposed versioned snapshot, not an RTL change

A future observation adapter can add a `snapshot_v1` request/response protocol with a capture sequence, frame epoch/FID/generation, current child epoch, tile/token where relevant, capture-edge timestamp, scope/reset-generation tag and terminal/error/cancel state. It should capture a coherent bank on one explicitly defined edge and hold the complete response until acknowledgement. Serializing that frozen bank is safe for coherence; independently reading live counter words over several cycles is not. A delayed busy/error/done **display copy** belongs in that response and must never drive original operational logic.

Define capture priority explicitly: reset, accepted restart, outer abort, internal cancel and final-event capture must have specified outcomes, with stale responses tagged or invalidated. A terminal response must include the last accepted output and physical matching ACK/discard events, and represent drained ownership. If sampling on the edge where a counter increments, capture its next value or schedule capture after that update; blindly copying pre-edge registers loses the final event. Child totals need child-epoch ownership so three per-plane invocations are not accidentally called one frame total. Preserve bit width/wrap and the existing first/last timestamp definitions.

Adding an output snapshot alone does **not** remove reset/CE fanout from the original counter banks. Retiming telemetry computation would be a separate experiment: register the event, timebase, owner and clear bundle together, preserve final-edge/flush/ACK semantics, and prove the resulting explicitly versioned observation schedule. Histograms in RAM, local clear distribution or serialized collection need independent same-bin/wrap/epoch proofs and actual mapped timing/resource evidence. None is presently implemented. Existing live ports/tests remain exact until a separately reviewed interface change explicitly changes their contract.

Primary AMD reset/control/pipelining context remains in [AMD control guidance](amd-control-guidance.md) and [reset/fanout plan](reset-fanout-plan.md). This inventory supplies concrete consumer evidence for those recommendations; it is not a new routed timing result.
