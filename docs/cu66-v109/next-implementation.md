This is a prioritized continuation plan, not another RTL change or a forecast of achievable timing. **All four completed native trials fail the fixed 10-ns component clock.** Both original seeds passed the full canonical comparison for each selected composition: 44 case profiles and 42 directed checks, exactly matching the frozen V108 stdout/events/cycles/canonical outputs. ## 1. Preserve the completed request experiment as negative evidence

The [request candidate](request.md), SHA `ac7260e749ace036495a162882fdb30fdb129d2c7ddde8df67bc2a8957f8f4b1`, derives from frozen FETCH SHA `4d6a16d0b89aa067fe3e7acc01351ea0bacac694cc63fb681a1471ee4683d044`. It prepares the first request in begin_fetch and later request address/bounds on the existing WAIT edge. Its [focused proof](../../experiments/python-gamebub-v109/request/results.json) and [full canonical proof](../../experiments/python-gamebub-v109/canonical-request/fault/results.json) both have actual RTL PASS, including stale-response rejections and actual request/response boundary, wrap, hold and retry scenarios. The public address expression, response expectation, cancellation, malformed full-width arithmetic and error priority retain their original schedule.

Its final [REQUEST setup report](../../experiments/python-gamebub-v109/native/20261108T122633998509Z/reports/route-setup-paths.rpt) is negative. The worst path starts at transform/fault_o_reg and ends at producer_cell_cache_reg[0]_i_86/ENARDEN: fourteen LUT levels, 11.748-ns data delay, 2.192 ns logic and 9.556 ns routing (**81.342% routing**). It traverses acknowledged-fault/base-abort distribution, ingress/scratch cancellation and coefficient/producer ownership control into a RAM port enable. ENARDEN is a primitive port-enable endpoint, not evidence that telemetry or a new write transaction alone causes the path.

The logical request-address hypothesis was grounded in initial B, but REQUEST does not remove this new fault-to-owner/RAM-enable dependency. Its worse WNS must remain visible beside its exact behavioral proof. Do not relabel the negative result as closure because an earlier arithmetic cone was shortened, or select another composition on an unmeasured timing prediction.

## 2. Prioritize same-edge quiescence and owned-fault locality

The final FETCH route's primary path launches at scratch state[0], then passes through scratch/child busy, start readiness, final-token ownership, retry/cancel and token validation into an inverse coefficient-word CE. It has **ten LUT levels**, 11.346-ns data delay, 1.758 ns logic and 9.588 ns routing (**84.506% routing**). Its near-worst inverse_fault_ack→Rice reservoir CE path is −1.599 ns with fourteen levels and 80.071% routing. This is distributed operational control, not coefficient arithmetic.

No path in FETCH's reported worst fifty launches from the older fetch_index or fetch_return source registers. Fetch-index CEs still appear as destinations of scratch-state control. Absence from fifty paths does not establish that every address/bounds endpoint passes, but it changes the priority: additional ingress byte-selector/last-byte/continuation work is secondary unless a newly measured route identifies that cone again. The [FETCH findings](fetch-route-findings.md) distinguish the remaining scratch selector secondary paths and why adding bank+REQUEST would not logically remove the primary busy/cancel or acknowledged-fault dependency.

The next narrow source-bound investigations are:

- **Co-register scratch busy/quiescence with every actual next-state assignment.** Pair **all** state writes with the exact busy predicate for that resulting state, retaining initialization, held-state and last-assignment priority. Include reset/abort, malformed/error branches, physical-request DRAIN, dynamic return-state transitions, final responses, FINISHED/FAILED and the final tile-completion override. DRAIN remains busy until the actual physical owner retires. Prove equality to `state!=IDLE && state!=FINISHED && state!=FAILED` on every public cycle, then propagate only equivalent local readiness/owner predicates where repeated decode is removed. Registering the existing combinational busy one edge later is not equivalent. Removing a decode does not predict a clock gain across the remaining ten-level distributed cone.
- **Co-register an owned unacknowledged-fault predicate/pulse only with complete acknowledgement-priority proof.** The current top's base_abort includes inverse_fault&&!inverse_fault_ack and reconstruction_fault&&!reconstruction_fault_ack. Ack clearing on reset, external abort and accepted retry, ack setting from current owned faults, simultaneous stage failures, sticky errors, new fault next state and replacement-start suppression all determine the exact event. A proposal must pair fault_next and ack_next on the original edge and prove cycle-by-cycle equality to the present expression, including externally asserted abort and accepted-start priority. A sampled copy of an already registered fault would be late. Do not register raw base_abort or reset one edge later, discard the one-shot acknowledgement ownership, or alter immediate input/output/publication fences to shorten the route.

Every further cut needs a concrete consumer/deadline inventory, reversible source binding, unchanged original assertions/goldens, focused and full canonical proof, and a separately authorized source-exact native comparison. A top-fifty family count is triage, not a census of all failing endpoints. Retain live cache tags, response ownership, cancellation and valid/ready fences on their original consuming edge while claiming cycle exactness.

The [Rice prefix contingency](rice.md) remains source/model preparation only, not selected or RTL-qualified. It targets a different prefix cone and does not structurally remove the measured fault-acknowledgement network. Scratch prefetch/bank changes likewise need their own measured comparison; initial B's smaller total setup deficit did not improve WNS. No timing exception, clock relaxation, silent cycle mask or favorable placement assumption supplies missing protocol proof.

## 3. Define a production telemetry/readback contract separately

The current OOC top exports a large parallel observation surface. Initial A/B check_timing reports list 12,888 output endpoints without output delay, consistent with roughly that many exposed parallel output bits; the existing production [core bus](../../fpga/rtl/moonshine_core.sv#L8) has a 32-bit readback value. This is an interface-scope difference, not evidence that removing output ports qualifies the unchanged CS88 top or produces a particular timing gain.

First refresh the [V107 status-use inventory](../cu66-v107/status-pipeline-inventory.md) against the actual selected V109 closure. Inventory concrete consumers and required edges. Debug-looking names can be operational: scratch debug_prefetch_use invalidates consumed prefetch ownership, and inverse dbg_launch advances its send state. Busy, ready, error, done, queue ownership, cache validity, used_bytes, bounds and launch decisions can authorize RAM writes, cancellation or new work. Keep those operational paths and their live sampling edges intact. Diagnostic copies must never replace them.

A lean production parent may instead define a new bounded, host-polled snapshot/readback API. Specify its register map/read handshake, capture edge, frame epoch/FID/generation, child epoch/token, scope and reset generation, timestamp, sequence number, valid/error/cancel/terminal state, atomic multiword read rules and acknowledgement. Freeze a coherent bank for serialized 32-bit reads. Include final accepted output and physical matching ACK/discard events in terminal snapshots; a pre-edge copy must not lose the final increment or mix epochs. Define counter width/wrap, saturation if newly chosen, backpressure, repeated reads, reset/restart invalidation and snapshot-overrun behavior explicitly.

Under that **new parent contract**, orphan observability banks may be left unconnected or removed only after proving they have no operational consumer. Wide live telemetry can retain counter/control logic and routing that a bounded production readout does not require. Merely attaching a snapshot to every old live output may retain the same banks and reset/enable fanout. Any trimming, event/timebase retiming or RAM-backed histogram is a separate implementation experiment with coherent ownership and same-bin/wrap/flush proofs. It has no implemented or measured gain here.

Keep the current CS88 focused/canonical contract and all its assertions/public checks unchanged. Qualify the new production wrapper/parent, its operational stream and new status schedule separately, with a new source closure and its own final route. A lean-parent pass must not be relabeled as a pass of the unchanged 12,888-output OOC interface.

## 4. If a registered kill/tuple fence is necessary, version the behavior

If same-edge equivalent predicates cannot satisfy the measured control timing, define a versioned registered-kill, elastic-handoff and final-drain architecture. Keep an immediate current-cycle publication mask and owner fences so a locally delayed private flush cannot expose stale output, accept an unauthorized tuple or retire physical work early. The existing one-slot boundary already owns a final stalled offer; a new register must account for that final owner before done/start-ready. Registering an already-registered fault or blindly delaying reset changes behavior and cannot honestly be called the current cycle-exact design.

Before implementation, define the revised ordered/public contract and independent goldens. Specify accepted-start versus attempted-start timing, local stage capacity, registered kill latency, flush propagation/acknowledgement, owner epochs, replacement-start priority, pending-request drain, and the permitted latency of ready/valid/done/error/status/counters. State the observable edges that change and retain immediate cancellation fencing wherever the new contract requires it. Every in-flight tuple must bind payload, mode/scale, token, frame/child epoch, validity and fault cause; a delayed status bit paired with a newer tuple is not a valid pipeline stage.

Preserve ordered accepted data, request/response ownership, reference-generation checks and validated output content. Accepted external memory/reference work remains owned until the matching physical response even after logical cancellation. Prove no stale tuple, output, write or publication can escape during the interval before a local registered kill arrives. Private speculative activity may continue only while it is unowned and cannot later become visible without fresh ownership. Define simultaneous failures, last output plus fault, held output, warm reset, flush completion and accepted replacement cases explicitly.

Use an independent latency-aware stream/transaction scoreboard with the newly specified ordering and time bounds. Keep the original cycle-exact implementation as a separate control reference, and explain intentional differences; do not delete its assertions, ignore counters, mask inconvenient cycles, shift traces until they match or regenerate expected results from the candidate. Canonical pixels/hash/HUD/reference behavior and malformed/error semantics still need independent goldens. Remeasure full-frame cycle cost and fences after any intentional pipeline latency or scheduling change.

## 6. Integrate and qualify the actual parent and physical service

Follow the [actual parent integration inventory](integration-gaps.md). [moonshine_core still instantiates jpeg_core](../../fpga/rtl/moonshine_core.sv#L91); the CU66/CS88 path needs negotiated packet/profile framing, bounded compressed-byte ingress, error recovery, fallback policy, reference/generation ownership, pixel conversion and safe framebuffer publication wired into the production parent.

The real [clock/reset topology](../../fpga/rtl/moonshine_top.sv#L14) has a 50-MHz input, 200-MHz transport/overlay, 100-MHz core/memory, phase-shifted SDRAM read capture and a panel pixel domain, with synchronized reset release. Integrate actual board clocks/I/O, generated-clock relationships, CDC ownership and reset behavior. Route the exact production part/top with valid constraints and close setup, hold, pulse width, routing, methodology and CDC gates. The component's single 10-ns XDC does not qualify this topology or its board timing.

Replay full fixed workloads through the actual BRAM/SDRAM controller and display arbitration with finite queues, refresh/read/write service and scanout deadlines. Exercise simultaneous reference reads, decoder writes, transport backpressure and panel reads, error/retry/reset and framebuffer handoff. Require independent canonical/reference/HUD/hash parity, no stale publication, bounded queues/stalls and zero scanout underruns. Check actual inferred primitives and controller timing; software-backed reference arrays do not establish physical memory service.

Only the separately implemented and measured parent can supply calibrated packet-complete→validated-publication distributions and maxima. Keep product hardware gates open until distinct-frame runs establish the requested 1,800 frames over 60 seconds followed by 18,000 over 600 seconds at 30 fps, plus the strict validated-decode endpoint criterion for every qualified sample. These are required evidence, not results or predictions of this component study.
