Every source route into a context start was inspected:

- A compressed METADATA handshake enters CONTEXT_START at band 0 only after all four descriptors passed. Held metadata cannot mutate counts/blocks; cancellation suppresses the handshake and child start.
- CONTEXT_END handshakes at bands 0–2 increment to the next validated band. Band 3 finishes. All descriptors were checked before the first context, and the same stored metadata is reused.
- Raw metadata chooses RAW, whose completion chooses RAW_END then FINISHED; it never starts a context.
- Every `begin_fetch` continuation is HEADER, DESCRIPTOR, CONTEXT_RUN or RAW. No retry/fetch continuation injects CONTEXT_START or a new unvalidated count.
- Reset, abort and replacement start suppress child start through `cancelled`; child reset/abort and parent reset/start priority discard the old owner. A replacement must receive and validate a new header and descriptors.
- CRC/header/length/count/k/padding/read-epoch/address failures enter FAILED before metadata. Context error has priority over parent state work; done advances only the existing validated owner to CONTEXT_END. Neither path changes count/blocks into an unvalidated start.

The narrow proposed change is a compile-time parameter with generic default false. Enable it only on the selected synchronous ingress context instance, leaving standalone and legacy instances at the original checks. Within the AC code-4 configuration expression, use `(!PREVALIDATED_EVENT_COUNT && event_count>start_limit)`. Keep the block/band bounds, k limits, DC exact-count check, zero-count/stream-bits code-7 branch, reset/abort priority, all invalid output assignments, counters and original assertions byte-for-byte. Since the removed predicate is false on every reachable enabled start, code-4/code-7 priority and parent malformed-packet failure cycles are unchanged. Removing the whole configuration guard would be unjustified.

Add an independent NON_SYNTHESIS assertion at the actual child-start event. Use zero-extended unsigned 64-bit operands for legal block/band checks, DC count equality and AC `count <= blocks*factor`. It must not use `count_threshold`, `descriptor_count_bad` or `start_limit` as its expected result. For example, `{32'd0,counts[band]}` and `{47'd0,context_blocks}` explicitly express the two operand widths. Preserve all current assertions rather than replacing them with this relation.

**The multiplier is still needed.** At context start, `limit<=start_limit` supplies WAIT_RUN's sparse-position bound/error 6 at line 4086. The proposal removes the product/comparison dependency from start failure/control; it must retain limit capture and runtime malformed-run checking. There is no promise the DSP itself disappears, nor that placement/routing improves. Even public invalid values require the new actual whole-ingress/context miter to remain cycle-exact.

An existing-edge alternative is to prepare/register the three constant limits (blocks×5/15/43) while the selected caller's owned block metadata is stable, then mux them at child start. The caller captures blocks at outer packet start, well before receive/header/descriptors/metadata finish, so preparation can use existing edges without a public latency change. Generic default must retain direct live-start-input semantics; a specialized path needs its own start-time wide-product equality assertion. This adds private FFs/mapping choices and is a broader experiment than removing a proven redundant rejection. Do not silently combine both.

Any future implementation needs a new namespace and actual whole-module old/new miter with generic-default behavior, enabled validated caller, all public/invalid values/counters/state, all historical goldens/assertions, AC/DC count boundaries, block 0/65,536/invalid values, high-u32 counts, empty streams, stalled/aborted metadata, restarts and late read responses. Current policies/native attempts remain frozen; this is a causal proposal, not timing closure or hardware qualification.
