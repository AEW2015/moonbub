# Contingency: versioned admission, registered local kill, and final drain

This is a concrete **unimplemented alternative** if the exact V110 predicates do not close the measured control paths. It is not a source substitution, RTL proof, timing result, or claim of cycle equivalence. V109 and the focused-qualified V110 source/proof namespaces stay frozen. Implement this only in a new namespace and a versioned top, provisionally `cs88_pipeline_v111_control`; retain the existing exact checker and its original goldens as the unchanged control reference.

## Why the exact pending pulse is one cycle wide

In the frozen V110 inverse and reconstruction bodies, `fault_o` has only two procedural assignments: zero in the original reset/start/cancel branch and `reason != 0` inside the original `fail(reason)` task. The candidate adds `fault_pending_o <= 0` at the beginning of the same main sequential process, then assigns `(reason != 0) && !fault_ack_i && !fault_o` inside that task. The default is essential: if a fault appears after edge E, the original top acknowledgement is still zero after E, so the pulse must be one in that interval; at E+1 the top observes the old fault and sets its ack, so the pulse must become zero even though the sticky fault remains one.

For pre-edge fault F and actual top acknowledgement A:

```
A' = 0       when reset || abort_packet || accepted_start
     A || F  otherwise
U' = F' && !A'
```

Every top ack-clear cause also clears the stage fault on that edge: external abort asserts stage cancel; accepted start drives stage start; reset is shared. A local peer/coefficient cancel clears F and U but leaves A under the original top rules. Otherwise a held F is acknowledged, giving U'=0, while a winning failure reason R gives `U'=(R!=0)&&!(A||F)`. This also covers a later failure while A is already one, and reconstruction's ordered response/state-machine fail calls: the final call supplies both winning R and U. Simultaneous inverse/reconstruction failures independently produce both original one-shot abort causes. Accepted retry clears both faults and acks together; old sticky errors retain their original accepted-start suppression. No raw registered fault is sampled one edge later.

The extra ack input is coherent only with the **actual parent ack for that stage and owner**. Substituting a delayed status, clearing ack on every peer cancel, or reconnecting another stage's ack invalidates the argument. Top assertions compare each pending register against its own fault and actual ack on every edge. The focused driver distinguishes external abort from local cancellation; the unchanged full pipeline must exercise the real parent wiring. This algebra explains the exact current candidate; it does not authorize relaxing its public schedule.

## Two specific source cuts

The current top computes `accepted_start` from live producer readiness, inverse/reconstruction busy and `coefficient_boundary.occupied`. Producer readiness includes child busy/draining; child busy includes scratch state. `accepted_start` then suppresses old sticky-error cancellation, which reaches inverse input readiness, malformed-current-token validation and every coefficient-word CE. The first proposed cut is a **registered admission credit**, not a registered copy of the live `start_ready` expression.

A parent admission register issues one credit only after generation-matched empty/flush/drain acknowledgements have been received from: producer plus refill queue and staging owner; child ingress/context/Rice; scratch write slot, request owner, prefetch owner and tile banks; coefficient boundary including its final offered token; inverse banks plus dequant/IDCT; the new residual handoff; reconstruction plus its physical reference owner. Local acknowledgements are stable until consumed or explicitly invalidated. Issuing the credit reserves all these resources: none may start new work independently. Thus `accepted_start = start && admission_credit && !reset && !abort_packet` has no same-cycle scratch-state/busy dependency. Scratch busy remains accurate telemetry and a local drain input, not a current inverse CE input.

Cache preload is another ownership claim. `cache_ready` is suppressed whenever `start` is asserted, as in the current producer. A partial cache-load acceptance revokes the unused admission credit on that edge; a simultaneous accepted start wins and no cache beat is accepted. A new credit requires no partial preload and coherent cache/reference identity. Acceptance latches the **whole** command: packet bytes, supplied frame epoch, accepted reference validity/FID/generation, quant-cache validity/identity and all four mode controls. Later changes on input pins cannot change an admitted command.

The second cut replaces distributed immediate **private cleanup** through `base_abort`/scratch publication/current-token validation with local registered kill requests. Keep an immediate **public** revocation mask from external reset/abort, qualified current-owner faults and physical-response failures. Distribute generation-tagged kill to local kill registers; local storage CEs and private handshakes use their local active generation, local error checks and local kill register. They no longer evaluate remote parent ack/readiness/start-suppression combinational logic. A revoked stage may change private state before its local kill arrives, but cannot publish, accept external work or transfer ownership to a new generation. Epoch comparison alone is insufficient if valid remains asserted at a public port: both halves of every external handshake must be fenced.

## Edges, ownership, and bounds

Use rising-edge transfer semantics. A transfer occurs only when valid and ready are both true immediately before that edge. A fault detected by sequential logic at E becomes visible just after E; it suppresses public transfers at E+1 and later. A pre-E handshake at E remains counted, including a last output or late arithmetic/input fault combination. Such a failed frame is never eligible for validated publication. External abort/reset asserted before E suppresses the transfer at E itself. This preserves an explicit boundary rather than claiming retroactive cancellation.

Use a private owner identity `(reset_generation, admission_sequence)` alongside existing frame/child epoch, FID, reference generation and token. Increment admission sequence on every admitted command; warm reset invalidates the logical owner without forgetting accepted physical transactions. Counter wrap is an admission error until the owner space is re-established with a complete drain. Old-stage sticky faults, queued tuples and delayed acknowledgements carry their original owner; they cannot kill or authorize the next owner even if externally supplied fields are accidentally repeated.

| Event | Proposed deadline and rule |
| --- | --- |
| Accepted start at E | Consume credit and latch command at E. Children consume registered start command at E+1. Input readiness cannot rise before matching start acknowledgements, first eligible after E+1. |
| Visible owned fault just after E | Public mask acts in that same interval. Local kill registers capture the generation-tagged request at E+1; local sequential state clears/invalidates by E+2 and returns flush acknowledgement. |
| External abort/reset sampled at E | Public transfers already masked at E. Local kill capture at E; local sequential invalidation by E+1. Warm-reset physical owners survive. |
| Private flush complete | Acknowledges no further private tuple for that owner can emerge. It does **not** acknowledge outstanding memory/reference work. |
| Physical drain complete | Acknowledges every accepted scratch request, reference request and staging/refill response obligation has matched and retired; mismatches do not retire the real owner. No finite deadline is claimed without a finite external service bound. |
| Retry permission | All matching flush and drain acknowledgements, empty elastic slots, no final offer/EOF owner and no partial cache load are required. Issue credit within one edge of that complete condition. With no outstanding service and a newly visible fault after E, earliest guaranteed credit is after E+3. |
| Successful done | Accept the final public pixel first, consume both EOF fences, complete all physical drains, then expose done within two edges of that join. A fault/abort wins over done. |

This adds a command edge and bounded local cleanup latency. It may also add elastic handoff stalls. None of these deadlines is a new claimed full-frame cycle budget. Derive end-to-end bounds using actual stage service bounds, offered data and external backpressure; measure the resulting counts with the original fixed workloads.

## Immediate public fences and physical service

At the top boundary mask `in_ready`, `cache_ready`, `out_valid`, `mem_req_valid`, and `ref_req_valid` for a revoked owner. Also mask the corresponding ready returned to each internal requester, so an internal producer cannot believe a masked request was accepted. Retain the original live response-owner comparators and ready rules for draining `mem_rsp_*` and `ref_rsp_*`. Response acceptance and discard remain observable during logical cancellation and warm reset. In particular scratch `DRAIN` remains owned until the matching `mem_rsp_epoch`, and reconstruction retains its full pending epoch/FID/generation/plane/tile tuple. A mismatched response records the error and leaves the true physical obligation pending; it cannot create retry credit.

Local delayed kill must not issue a new physical write/read/reference request during the delay. The top fences enforce this immediately; the stage kill removes the speculative offer later. An already accepted physical write may complete after revocation into old scratch ownership. New admission cannot reuse its storage/identity before the matching drain acknowledgement. Public pixel writes must use a provisional frame buffer owned by the revoked generation and never become a published reference/display frame. This top-level proposal alone does not implement the production framebuffer publication protocol.

A future lean wrapper can make internal coefficient/residual/lookup ports trace-only, but the current top exposes them as public outputs. The versioned top must explicitly mask their `*_valid`, `*_req`, `*_rsp`, `*_ready` and launch/commit observation bits when `trace_live` is false, and export owner/trace-valid metadata for raw state and payload views. Internal handshakes use separately named local wires; masking an observation cannot silently change what an internal module consumed. No operational `dbg_prefetch_use` or `inverse_launch` may be replaced by a masked diagnostic copy.

## Elastic final-token and EOF contract

Keep the existing coefficient tuple intact: parent owner, frame epoch, child epoch, plane, qscale, block, tile, qcell, index, signed value, metadata-invalid and domain-invalid bits. Token assignment still occurs inside inverse on the first accepted coefficient. Use a one-entry owned coefficient handoff and a separate EOF-pending/final-offer owner, retaining the present `done_pending`/`final_wait` semantics. If producer done first appears with `in_valid&&!in_ready`, record that final offer before EOF; the offer must be accepted or explicitly canceled before EOF can advance. Producer completion cannot clear or overwrite the offered tuple. Simultaneous downstream pop/upstream push retains the replacing tuple and all sidebands. EOF can advance only after the slot and final-offer owner are empty.

Add one equivalent owned residual handoff containing parent/frame/child identity, inverse token, plane/qscale/block/tile/qcell/index and signed residual. Inverse done may arrive while that slot holds its final accepted residual; the residual EOF remains pending until reconstruction accepts that tuple. Reconstruction cannot treat inverse done as input completion before that EOF. Under backpressure all data and sidebands stay stable; one empty slot permits one accepted tuple, never two. Revocation cancels data/EOF ownership and eventually acknowledges the empty stage, while physical-response ownership remains separate. Successful final drain joins both EOF acknowledgements, final public pixel acceptance and all physical drains. `coefficient_done`, `inverse_done` or a private math-done bit alone cannot authorize top done or retry.

## Independent ordered protocol checker

Build a new scoreboard driven by **external accepted events**, not internal candidate state. At `start&&start_ready`, allocate an oracle transaction from the latched command and immutable packet/reference/cache fixtures. The existing independent entropy, quantization/IDCT and canonical pixel/reference/HUD/hash goldens supply expected ordered content. Maintain separate queues for expected coefficient/residual tuples, pixels, scratch physical requests and reference requests; compare identity, address/bounds, data and error location where externally meaningful. The scoreboard owns pending request records until exact matching responses and separately counts canceled/discarded replies. Never remove a request because a candidate busy bit dropped.

Model admission, cancellation and the two EOF owners as a small protocol machine with the deadlines above. Derive expected handshake counts, terminal cause, reset generation, drain completion and publication eligibility from those events. Check current-cycle public masks, held-token stability, no duplicate/lost tuple, no cross-owner effects, final-offer-before-EOF, no done-before-last-pixel/drain, and no retry before every old obligation retires. Latency checks use explicit eligible-event deadlines with stalls/service delays supplied by the testbench; they do not align traces until they match.

Directed cases must cover: done plus a stalled final coefficient; full slot with simultaneous pop/push; inverse done while residual final slot is full; last pixel plus local fault; simultaneous stage faults; external abort plus offered start; accepted retry with old sticky faults; peer cancel without ack clear; reset during pending scratch write/prefetch/reference reads; stale/mismatched responses before and after a genuine response; all combinations of flush ACK and physical drain ACK order; late duplicate ACK; cache partial-load/start collision; and attempted replay of an old tuple using otherwise valid public epoch/FID fields. Use independent counters and fixture hashes in the receipt. Actual source-bound RTL, full fixed canonical workload coverage and final native route remain required before selecting this version.

The immediate mask and owner comparators can themselves become routed critical paths. Measure those paths after implementation; this contract does not guarantee 100 MHz, and no exception or relaxed clock follows from adding the registers.
