# Cursor payload ownership and causal feasibility audit

The proposed cursor payload split has no identified production public/invalid-output counterexample in the audited source. The key condition is **same-edge new-owner restoration**: all real cursor uses belong to an active owner, and every replacement owner enters through an IDLE edge that clears the original and proposed cursor RFs before consumption. This supports a new owner-scoped miter; it does not preserve every raw inactive private RF bit.

The actual [parallel-prefix final route](../../experiments/python-gamebub-v110/native/20261108T145904974022Z/reports/route-setup-paths.rpt), SHA-256 `df151d920ae21b46d19e05d6e868373f58510afc10dfd498a41777c65c7a6be7`, reports `read_segment_reg[1]/Q → cursors_reg[1][29]/R` at **−1.654 ns**. Its data delay is 11.140 ns: 3.239 ns logic and 7.901 ns routing (70.926%), fourteen levels including two CARRY4s and a MUXF7. Thirty-nine top-fifty endpoints are cursor reset pins; forty paths launch from `read_segment`. This is a source-specific payload/reset cone, not a reason to add a generic fanout directive.

The authoritative selected scratch is [V110 busy](../../fpga/experiments/cu66-v110-busy/packed_scratch_v91g2.sv), SHA-256 `e9a70463b78c0afbbded2358fd9b4ca7f600c695d9251b0cf3d202a74ad21478`. Its 96 cursor bits have only two original write forms: zeroing all three banks on a valid IDLE begin, and incrementing the selected bank after a good cache-hit AC record. There is no cursor output port and no other actual-origin module in the eighteen-source closure refers to the cursor RF hierarchically.

| Cursor consumer | Exact lifetime/sink |
| --- | --- |
| AC_CHECK | Cursor-versus-count chooses fetch/progress. `debug_tile_publish` additionally requires tile mode, AC_CHECK and no cancel/response failure. |
| AC_FETCH | Captures `read_address=starts[read_band]+cursors[read_band]*4` under the original controller priority. |
| AC_EXTRACT | Cursor zero/nonzero selects the non-first-record monotonicity check. |
| EMIT | Non-raw prefetch candidate address/count, additionally gated by prefetch mode, sealed owner, no outstanding/offer/cancel and error zero. |

IDLE, DRAIN, FINISHED and FAILED consume no cursor value in these paths. `mem_req_addr` comes from held `transfer_address`; `read_address` is a register captured in AC_FETCH. Neither is an unmasked combinational IDLE cursor port. `debug_prefetch_use` depends on owned state/cache/tag/read-address, while `debug_prefetch_launch` derives the guarded candidate above. These actual outputs and invalid payloads remain proof obligations, with no debug exemption.

The proposed independent cursor FFs clear **every** IDLE edge. On `state==AC_EXTRACT`, they increment only the selected band when the pre-edge selected cache is valid and its line address matches. They deliberately ignore global kill/error priority and malformed-record validity for this private payload; the original FSM, errors, heads, head-valid bits, memory controls, dense data and public debug retain their exact priority and equations.

The reason a speculative increment is unobservable is retirement, not masking arbitrary live data. A cancelled/error/malformed hit that does not perform the old increment moves the owner to IDLE/DRAIN/FAILED, or a terminal FINISHED override. None can subsequently consume that cursor. DRAIN ignores stale dynamic return state, holds through a wrong ACK, and returns only to IDLE after real owner retirement. A valid subsequent IDLE begin clears **both** cursor RFs to zero on its original edge. Invalid/unaccepted begins or preload noise cannot create a cursor-consuming owner. Reset/abort before admission, simultaneous begin and response error, held physical owners and late ACK therefore do not require copying already-registered public busy/error one cycle later.

**Cache misses must not increment.** READ_REQ/READ_WAIT returns to AC_EXTRACT for the same record ordinal. The model's negative control shows that increment-on-miss creates unequal live cursors immediately in READ_REQ and can change the later monotonicity/address behavior. The candidate retains this guard.

The [owner model](../../experiments/python-gamebub-v110/cursors/model.json), SHA-256 `f8208b54212db97c8e3837388f97ac7dd475063ed9677ad3e5faf9381f000670`, passes 111,360 per-bank transition cases, including arbitrary retired values and modular wrap. It also checks the retired physical-owner graph: 512 nodes, 9,216 edges and 192 new-owner restoration edges, covering wait/wrong/matching ACK, reset/abort and simultaneous valid/invalid begin. Per-bank equality/zero/equal modular increment gives the 32-bit induction; unchanged live-state controller transitions preserve it. This is a source-bound finite abstraction and algebraic ownership argument, **not formal whole-RTL/four-state/reachability proof**.

The old busy proof compares `verify_cursors` unconditionally. That proof remains frozen. The new miter must scope **only that verification-private field**, requiring equality whenever either raw DUT state is live. It must compare raw states before scope, retain unconditional production public/invalid/debug/memory/read-address comparisons, and preserve every other raw observation/oracle/assertion. Otherwise an owner mask could hide a real state or operational mismatch. The implemented focused proof and retained failure are documented separately in [cursors.md](cursors.md).

The [machine-readable analysis](../../experiments/python-gamebub-v110/cursors-analysis.json), SHA-256 `edf9e4ba777c68c0f956af089ddf2c3d468e81dc55cda4fe77819b4f22c5e530`, pins the actual native receipt/source/path, complete cursor-use inventory, model, candidate, focused evidence and limits. The split structurally simplifies the cursor clear/increment authorization, but actual mapping may still retain cache/bank selection on increment. No native gain, recovered slack or MHz is predicted. Full canonical qualification and any separately authorized native experiment remain necessary.
