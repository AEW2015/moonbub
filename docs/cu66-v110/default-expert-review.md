## Method and evidence

The only synthesis-method command change is removal of `-directive RuntimeOptimized` from the existing fresh-RTL `synth_design`. The additional Tcl differences are comments, a guard requiring RTL mode, and explicit intended-method metadata in `settings.tsv`. Top, part, hierarchy mode, clock loading before synthesis, Opt/Place/Route directives and absence of a physical-optimization step remain unchanged. No retiming option is added.

AMD's [2026.1 UG835 synth_design reference](https://docs.amd.com/r/en-US/ug835-vivado-tcl-commands/synth_design) documents `default` as the default directive and describes retiming as optional for non-Versal devices. [2026.1 UG901 synthesis settings](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/Using-Synthesis-Settings) explains that RuntimeOptimized skips some RTL/timing optimization to shorten synthesis. These facts justify a controlled comparison; they predict no timing or resource gain.

Reports only query/write observations; no KEEP/DONT_TOUCH/fanout constraint or other netlist property is introduced. The runner's Docker command/resource/mount expression and its memory/report-parser functions are AST-identical to the existing runner. Additional runner logic checks source/control/policy bindings and adds explicit Default-method metadata and actual log capture.

`observed_synth_directive_log` is extracted from the **actual future tool transcript**. The same expression correctly finds `runtimeoptimized` in an existing actual RuntimeOptimized log and returns no match when the line is absent; the recorder stores `None` in that case. It does not fabricate an observed `default` from intended settings. At this gate's review time, there was no actual Default log. An absent or unexpected value requires post-run method review before claiming a matched Default comparison; the hardened guard also prevents a positive validation repeat without an actual observed `default` line.

Changed Runtime control/policy/source/proof/directives/method/CLI/start mode, absent synthesis/clock provenance, inherited checkpoint clock, repeat ancestry, missing/wrong actual directive, nonterminal/nonpositive status and changed run/report/XDC recipes all fail. The author's separate two-positive/sixteen-negative guard-test artifact is also pinned. No simulated positive-parent fixture is represented as a real positive route.

Three operational conditions remain explicit:

1. Docker process-count checks are **not an atomic global semaphore**. Root must serialize slot grants/dispatch so simultaneous callers cannot both pass the same count. This review does not authorize another process or a premature Default preflight.
2. Any positive repeat must pass the shared parent guard at preparation and launch, plus its own independent preflight audit. Exact functional recipe/directive equality and observed Default-method provenance are now enforced automatically; the old repeat-binding gap is closed.
3. Read the actual observed directive and complete final reports after execution. Intended-method metadata alone, an absent log match, a positive synthesis estimate or a single positive route does not establish the required repeated component result.
