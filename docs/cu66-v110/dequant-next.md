# Dequantizer remaining FETCH data cone and one existing-edge candidate

The retained V109 FETCH top fifty contain 15 dequantizer paths, ranked 5–7, 9–13, 21, 43–45 and 48–50, with slack −1.564 through −1.483 ns. All launch from `group_index_reg[1]_rep__1`, traverse the same DSP `out_dequantized1__5` at `DSP48_X0Y6`, and end at different packed-output bits. This is one shared arithmetic/control root with multiple endpoints, not fifteen independent multiplier roots. It is secondary to the FETCH scratch-state worst path (−1.635 ns); its position after the current V110 changes requires new native evidence.

The authoritative [FETCH receipt](../../experiments/python-gamebub-v109/native/20261108T121030620057Z/receipt.json) maps historical `v69/inverse/cu66_dequant.sv` to actual [V107 payload-reset dequant](../../fpga/experiments/cu66-v107-payload-reset/cu66_dequant.sv#L17), SHA-256 `579cb5d397e6638c0533fd54250e161612bdaed74117a29475afbab648aec7fb`. All eighteen actual origins and corresponding retained source snapshots were SHA-checked. The unchanged quantizer header is SHA-256 `e0d5ae446155c1e295e0add487a30fec9c765cbafc0fabb15d248285ed22dca7`.

The worst dequant path is `group_index[1]_rep__1/Q` → LUT3 → LUT6 → LUT6 → DSP B[3]→P[19] → LUT2 → `out_dequantized[1259]/D`. Its 11.413-ns data delay is 4.608 ns logic and 6.805 ns routing (59.623%), with five logic levels including the DSP. The multiplier arc alone is 3.656 ns. The report counts FF clock-to-Q in its logic delay. The 10-ns requirement, −0.049-ns skew and 0.035-ns uncertainty are unchanged.

These are actual optimized-netlist names, not a unique mapping of each LUT to an RTL expression. The source causal chain is exact: current group index selects the quantizer ROM position and the packed coefficient; chroma, scale, rounding and clamping determine `q`; those selected operands feed a combinational signed multiply; the current group selects its 160-bit destination within the 1,280-bit public output. The [native DSP table](../../experiments/python-gamebub-v109/native/20261108T121030620057Z/reports/route-dsp-registers.tsv) confirms all eight dequant DSP48E1s have **AREG=0, BREG=0, MREG=0, PREG=0**. Different inverse/ingress DSPs have different register attributes; their attributes do not establish dequantizer pipelining.

The strongest zero-public-latency candidate is to prepare **both next-group multiplier operands at existing edges**. On the accepted IDLE edge, capture group-zero signed coefficients and their fully scaled/clamped quantizers from current `in_*` inputs. Each MULTIPLY edge for group `g<7` writes the original group-g product and simultaneously prepares operands for `g+1` from the owned saved payload and sidebands. Each original MULTIPLY result edge then sees direct matching operand registers feeding the DSP; the ROM, scale and coefficient selection terminate at those operand registers instead of sharing a cycle with multiplication. Eight lanes require 192 operand bits before any physical register absorption. Seeking DSP AREG/BREG packing is reasonable, but its inference and timing must be measured from the new source-exact native netlist.

This uses available edges already present: acceptance precedes the first result by one full cycle, and each result edge precedes the next result. Keep the original group index and exact output-slice write edge. Capture group zero from live inputs, not pre-edge saved payload; capture later groups from owned saved payload, not new input noise. Preserve signed16 × nonnegative9 multiplication, signed25 product and the original 20-bit truncation. Retain all current coefficient RF capture semantics and original quantizer helper arithmetic. Reset/abort must retain priority over result publication, bad/all-zero acceptance must keep its immediate HOLD_TILE path, and HOLD_TILE stalls must not advance ownership. Group seven must finish on its original edge.

Public partial payload is part of the contract even when `out_valid` is false: the inverse parent continuously exports `dq_data` as [dbg_dequantized](../../fpga/experiments/cu66-v109-fault/cu66_inverse_stream_v91j.sv#L955). A proposal that merely inserts MREG/PREG or registers the multiplier result delays those visible partial writes and final validity unless its schedule changes. Such a result-stage proposal needs an explicitly changed public contract. The existing-edge operand candidate above can preserve the current contract, but it still requires proof.

Require an owned-MULTIPLY invariant comparing prepared operands/products with the original source function, a complete old/new dequant pair with independent arithmetic goldens and cycle-by-cycle public vectors including invalid partial output, every group/reset/abort boundary, changing unowned inputs, HOLD stalls, alternate owners, all scale/chroma cases, coefficient limits, and bad/all-zero fast exits. Then require original full canonical checks on both seeds and a separately authorized source-exact native comparison. No recoded RTL, simulator, synthesis, implementation or hardware run was performed for this read-only analysis. No gain or achievable MHz is predicted.
