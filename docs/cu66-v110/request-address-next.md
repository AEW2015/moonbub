# Request-address contingency after the Default route

The frozen V109 REQUEST body is a source-matched contingency for the newly measured Default request-bounds cone. It removes the live address calculation from operational request bounds and RAM request payload on existing edges, with no public cycle change. It does not remove the public live address expression, every band-dependent context path, or guarantee a better route. No composition, preflight, RTL change or native run is authorized by this assessment.

The actual final Default result is WNS −1.199 ns. Its worst path launches from ingress `band_reg[0]_rep__0` and ends at ingress `state_reg[0]/D`: 15 levels, five CARRY4s, 11.072 ns data delay (3.241 logic + 7.831 route). The expanded path explicitly traverses `stage_read_addr[12]` LUTs, the address carry chain through bit 24, a `stage_read_req` LUT/CARRY4 bounds chain, then mapped context/ingress control LUTs. There are 36 band launches among the 50 reported paths. Optimized context instance names are aliases; they do not prove each downstream LUT implements the literal context RTL signal suggested by its name.

The current FETCH body (`4d6a16d0…`) computes the descriptor's final byte as `fetch_base + lengths[band] - 1`. This feeds both full-width comparisons in `stage_read_req` and the FETCH_REQ bounds-failure branch. Thus the measured band→address-mux/arithmetic→bounds→operational-control dependency has a concrete source counterpart. The full-width bound includes both `size_bytes` and `MAX_PACKET_BYTES`; truncating to physical RAM width would be incorrect.

The REQUEST derivative (`ac7260e7…`) makes these exact changes:

- `begin_fetch` captures the initial base and its complete unsigned bounds predicate. Every fetch starts at index zero, so the original address is that base.
- Every FETCH_WAIT edge speculatively computes the next six-bit index, complete 32-bit address and bounds predicate. Header 41→42 uses the original trailer jump; descriptor 5→6 uses `fetch_base + lengths[band] - 1`; modulo-64 index and 32-bit address wrap remain exact. A successful nonfinal response simultaneously advances the original index and enters FETCH_REQ.
- `stage_read_req` and the FETCH_REQ bounds-failure branch consume `prepared_request_in_bounds`; accepted RAM reads and `ram_addr` capture consume `prepared_request_addr`.

It does **not** separately register `lengths[band]-1`. It registers the complete selected address and bounds at the existing preparation edges. The newly introduced private registers have no reset/abort enables. WAIT preparation occurs before the original reset/start/error priority; values computed on final response, failure or cancellation are unowned, and a later begin_fetch replaces them before fresh request ownership. Existing frozen FETCH response-expectation capture/comparisons remain unchanged.

Consequently, current band/length/address arithmetic no longer directly feeds the request-cycle bounds decision, failure decision or RAM request address capture. Arithmetic moves to the preparation register inputs and can become the next critical path. No new cycle is inserted.

Important surviving dependencies are explicit. `stage_read_addr = fetch_address` remains unchanged in **every** state, including invalid cycles. The request-edge `expected_fetch_addr` capture also retains the live address. `stage_read_req` still immediately rejects cancellation and active-context error or done. Global priority still tests live `ctx_error`/`ctx_done`; neither is replaced or delayed. Descriptor validation, band-selected context parameters and replay base preparation remain. The old source therefore cuts the address/bounds portion matched by the Default report, not the entire context-done/error cone. A synthesis report alone cannot establish that all 36 band paths will disappear.

The old qualification is substantive but scoped. The focused complete-ingress miter compares every public output unconditionally, including `stage_read_addr`, response addresses/epochs, invalid values, debug, counters, metadata and capacity outputs. Its `mismatch` expression has no request-valid mask around address equality. Both seeds together cover 15,496,047 exact public cycles and 1,509,288 independently derived golden coefficients. Each seed completes 76 packets, 36 request/response-edge abort/reset/restart cases, eight actual synthetic-context RAM requests and two full-width rejected addresses; header/trailer/descriptor boundaries and wrap cases are included. The inherited capture fixture and all six stale-response assertion rejection subprocesses remain.

The new private prepared address is **not** asserted equal to the old live address in every inactive state. Added production assertions require prepared address and bounds equality in uncancelled FETCH_REQ, including out-of-bounds requests. Synthetic tests that directly force FETCH_REQ initialize its added private fields from an independent original formula; they do not sample candidate readiness or response data. The public live address still compares exactly during those tests. No all-private-state equivalence should be inferred.

Old complete canonical integration passed 44 profiles and 42 checks, seeds 107601/107602, with original V108 events, cycles, invalid outputs, counters and canonical bytes retained. This used V109 fault bodies, V108 scratch and older Rice/dequant/producer bodies. It qualifies neither the new V110 cuts nor cursor composition. A future source-only composition requires a new full canonical proof with its explicit private cursor scope; old proofs and goldens must remain frozen.

The old REQUEST route itself was negative: WNS −2.275 ns, 0.640 ns worse than V109 FETCH, with worst transform fault→producer ROM enable rather than request address. Its 50-path report contains one band launch at −1.795 ns, through a DSP and context arithmetic/checks, with no `stage_read_addr` instance on that path. This supports the narrow cut's relevance while demonstrating that other band paths survive; it is not an apples-to-apples timing comparison with Default or V110.

Recommendation: retain REQUEST as a directly matched, already behaviorally tested source contingency if the current cursor run remains negative. Root should select any composition and methodology only after that actual result. Reuse of the frozen body would still require new composition qualification and an explicitly authorized bounded native experiment. No clock prediction follows from this assessment.

Read-only checks verified all 18 current/snapshot sources for both actual routes, all old focused source/artifact hashes, all canonical source/artifact hashes and decompressed raw event/canonical hashes. The seven-edit recipe replayed in memory to the exact frozen REQUEST SHA. Only this note and the companion analysis JSON were written.
