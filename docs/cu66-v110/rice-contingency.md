## Guarded semantics and unchanged observables

For parallel PREFIX, `window=min(remaining,15)` and `needed=window`. A sequential consuming branch requires no earlier request/input acceptance, no held response/sticky failure, nonempty window and `can_step=(available>=window)`. Thus every position below window is owned. A masked and unmasked first-one rank either identify the same first one below window, or both identify no one below window. An unowned first one at or beyond window still gives the same `zeros=min(window,rank)`, `found_one=(rank<window)` and selected `take_bits`. Truncation, ordinary/escape suffix selection, quotient and all stored updates therefore have the same inputs on every consuming edge.

Serial PREFIX uses one fixed first reservoir bit and one-bit consumption; it does not select prefix rank/zeros/found. SUFFIX width/extraction and zero-width suffix handling are independent of the prefix tree. Input acceptance, malformed full-width word priority, reset/start, sticky error responses, held output values, count-input-wait and stall accounting retain their original equations and ordering. The full raw reservoir is unchanged by construction if these selected updates remain equal; that is still an RTL proof obligation rather than a waived comparison.

There is no consuming counterexample in the audited two-state guard domain `available=0..64`, `window=0..15`, arbitrary fifteen-bit reservoir prefix. A private unused counterexample is deliberate: available zero, window fifteen and reservoir bit 63 one gives masked rank fifteen versus unmasked rank zero, but `can_step` is false. The old exhaustive model explicitly allows arbitrary nonzero unowned bits: it represents 68,157,440 combinations in 33,280 exact classes after checking all 32,768 prefix words against both linear and balanced ranks. It was read and hash-checked here, not rerun or promoted to RTL evidence. No arbitrary four-state/reachability proof is claimed.
