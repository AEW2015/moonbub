Preparation only: no compilation or simulation has been executed by this worker. The module keeps the exact frozen `cu66_row_write_hash_join_v91l` name and port interface from `fpga/experiments/cu66-v91l-rows/cu66_row_write_hash_join_v91l.sv`: 64-bit request data, request byte count eight, epoch/token/bank/address ACK matching, expanded byte output and canonical/HUD metadata. It changes the intended schedule from one serialized row to **three eight-byte payload slots, one physical pending ACK, and ordered hash delivery**.

The fill, request and hash ring positions advance independently. A slot is free, filling, ready for request, physically pending, or successfully ACKed for hashing. Row A can drain hash bytes while row B retains physical ACK debt and row C fills. The ring accepts at most 24 payload bytes, with no speculative same-edge credit from a freed slot. Requests retain FIFO order; hashes retain accepted input byte order. A matching successful ACK qualifies exactly that row for hashing. Canonical plane/tile metadata remains fixed within a row and byte index increments; HUD preserves the first byte's metadata fields while continuation plane/tile/index inputs remain ignored as in the original module. `in_last` is accepted only on byte eight and appears only on expanded byte eight.

Warm reset/cancel immediately masks input/request/output valid handshakes, discards local partial/ready/hash work, and retains any accepted physical debt until its exact matching ACK. Wrong epoch, token, bank or address ACK poisons error `0x81` while retaining that debt. Matching error ACK retires the debt with `0x82`; invalid first/continuation input uses `0x83`/`0x84`. Faults discard queued local work and prevent further hash publication; prior successfully ACKed hash bytes accepted on the fault edge remain counted as accepted. A malformed new input can coincide with accepting an older complete row's request: the newly accepted physical lease survives that flush. Start requires fully drained state, resets per-start counters/error, and retains the monotonic wrapping token. Cold power reset still requires external physical quiescence.

`count_drops` counts all accepted input bytes that are discarded, including bytes retained solely to drain canceled physical debt. It satisfies `count_outputs + count_drops <= count_inputs` at every checked edge. As before, wrong ACKs do not count as matching ACKs, and at most one request is unacknowledged. Fill, request and output stalls retain their complete valid tuples. The slot payload count is exactly three 64-bit registers; metadata/state is separate.

The debug `state` is an aggregate priority view: physical pending → WAIT_ACK=3; otherwise current hash owner → DELIVER=4; ready request → OFFER=2; partial fill → FILL=1; otherwise IDLE=0. Concurrent progress means WAIT_ACK can coexist with valid output and input readiness. `fill_count` reports the current partial fill, otherwise eight for a current full/physical/hash owner, otherwise zero. `deliver_index` names the current hash byte.

The raw tuple **outside valid intentionally changes** with slot selection; it is not an exact-cycle equivalence claim against the old serialized module. Consumers must qualify request/hash tuples with their valid signals. All valid-stalled tuples remain stable. Root's parent selects frozen byte control or this row candidate using `ROW_WRITES`; this module adds no interface parameter.
