# V118 reconstruction timing architecture

This candidate moves reconstruction ownership checks off the residual-bank write-enable path and narrows each canonical destination write to128 bits. Routed timing remains a separate qualification requirement.

The incoming complete residual tuple and its expected owner snapshot are captured on acceptance edge E. A registered validation result, expected index and signed24-bit payload are prepared on E+1. Only a good validated tuple commits to the residual bank on E+2. Acceptance can run every edge. `fill_index` reserves acceptance positions; `count_residuals` counts committed words. `accepted_last` stops acceptance after word63 while both stages drain. The math/reference transition occurs only on validated commit63. The first validation fault flushes both pending valid bits and revokes both tile owners; already accepted younger words cannot commit or publish. Reset, start and cancel mask public offers immediately and flush the stages. No additional frame/tile payload buffer is introduced.

A completed math response remains in the existing engine's512-bit output storage. The inactive canonical bank receives four128-bit writes on four real COPY edges. Each bank has four registered one-hot lane enables, each serving sixteen byte registers. The engine's `out_ready` is asserted only on beat3. The destination acquires `O_READY` only after allfour writes and final ID/error metadata copy. Its older READY peer remains immutable while held. Cancellation may perform the currently armed private128-bit write, but cannot grant a logical owner; remaining private bytes stay unchanged and a retry overwrites allfour lanes before publishing.

This intentionally changes the timing contract. Residual commitment moves from acceptance E to E+2 and canonical copy requires four edges instead of one. The old V117 atomic-copy fixture remains unchanged in its original directory. V118 replaces that one-edge-only expectation with stronger every-edge checks of all512 destination bits in both banks, unchanged-byte conservation, final metadata, and cancellation at every beat for reset and cancel. No exact V117 cycle equivalence is claimed.

The focused bench keeps the original independent pixel clamp/reference equations, all32768 geometry inputs, three complete canonical frames, ownership/order/held-head checks, eleven malformed residual fields, wrong reference tags/errors, debt-preserving warm cancellation/retry, mode errors and partial EOF. New checks inject malformed tuples at indices0,7,61 and63 and require error4 exactly at E+2 with no malformed/younger commit. Four-beat engine stability and accepted/committed conservation assertions are active in RTL.

Physical reference-request debt retains the original independent owner. The `fail` task does not clear `ref_pending`, pending address/tag fields or the accepted reference-response obligation. Only a matching physical acknowledgement retires that debt.

Source: `fpga/experiments/cu66-v118-reconstruct/cu66_reconstruct_stream_v91k.sv`. Focused runner: `python3 scripts/cu66-v118/reconstruct/qualify.py --run --root-grant ROOT_GRANTED_SLOT`. Root dispatches this command within the global two-job resource policy. The selector and receipts are under `experiments/python-gamebub-v118/reconstruct/` and record whether RTL actually ran, immutable source snapshots, strict compiler arguments and raw failures. Preparation alone is not a simulation pass.

Reference-response faults have priority over normal reconstruction work. V118 suppresses that edge's normal FSM/pipeline actions when `response_failure` is true, preventing a normal state transition or younger residual commit from overriding `fail(3)`. The registered public fault/status interface and physical acknowledgement lease remain unchanged. Counters for an aborted faulty frame can therefore differ from V117; successful drained-frame counts and canonical outputs retain their exact functional checks. A faulted frame's provisional private work is not a publication result.
