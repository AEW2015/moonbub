# V129 125 MHz: admission RAM read-enable candidate

**Provisional route evidence, not timing closure:** the generated [50-path report](/home/lori/gamebub-build/cu66-v69/v129-parser-scratch-125-20261111T003806793713Z-16aa77/results/route-setup-paths.rpt) shows setup slack −1.257 ns from `base_kill_valid_reg` to admission `memory_reg_0_5/ENBWREN` at an 8 ns period. The second path is another RAM enable at −1.229 ns. The worst path has 8.730 ns data delay, 11 LUT levels, and 6.848 ns (78.4%) of routed net delay. It propagates through child cancellation/readiness, refill `child_in_ready` and `queue_req_valid`, then admission RAM gating. Those are mapped netlist names and fanouts, not independent proof of a single RTL statement's causation. The next reported path already misses by −1.076 ns into `prepared_successor_tile` enables, so eliminating this first path alone cannot be assumed to close timing.

The selected [admission source](../../fpga/experiments/cu66-v128-padding/cs88_admission_v91i2a.sv) has one read-first synchronous packet RAM: `memory_read_enable = stage_read_req || (replay_req && replay_ready)`. The [producer](../../fpga/experiments/cu66-v127-owner/cs88_coefficients_v91k.sv) supplies the replay request through the [two-owned-entry refill queue](../../fpga/experiments/cu66-v91i2b/byte_refill_queue_v91i2b.sv), whose pop-dependent request eligibility depends on child readiness. `replay_ready`, `stage_read_req`, response valid and tag updates explicitly gate reset/start/abort. Both public protocol and that queue's event ordering remain authoritative.

## Candidate experiment: local speculative RAM read

In a new isolated candidate only, decouple the **physical RAM read enable** from the deep replay request/cancel chain. During `FETCH_REQ`, select the latched fetch address. During `FINISHED`, speculatively clock the read port from a locally bounded version of the current replay address even if no logical replay request is accepted. For all other states leave the physical read disabled. An invalid or out-of-range speculative address must be clamped to a valid location within the 49,152-byte RAM; this local guard must itself be checked for timing. `FETCH_REQ` and `FINISHED` are distinct states, so the original accepted-read arbitration and address apply. The RAM's `stage_write` gate remains exactly as before; never speculate a write.

Keep **logical** `stage_read_req`, `replay_ready`, request acceptance, `replay_rsp_valid`, `ram_addr`, `ram_epoch`, counters, and all same-edge kill masks unchanged. The speculative result is unowned unless the original request accepted; it must never manufacture a response or queue entry. The raw `ram_data`/`stage_read_data`/`replay_data` buses currently expose the held RAM output even when invalid, so extra reads can change their invalid-cycle values. This is **not an exact all-public-signals cycle-equivalence claim**. First determine whether invalid data stability is a required contract; if it is, retain it with a separately proven output-hold mechanism, or reject this candidate. If it is not, record the precise valid-qualified equivalence contract and explicitly compare all non-data public outputs every cycle. No timing or power improvement is assumed; extra RAM activity may increase power and a new address/enable path could become critical.

## Required checks before promotion

1. Derive the candidate and retained original from frozen source hashes; separately simulate the real RTL with read-first RAM behavior. Check all 16-bit address boundaries (including 49,151/49,152), idle/uninitialized replay address, `FETCH_REQ` priority, sequential valid replay reads, bubble cycles, and reset/start/abort coincident with each request and pending response. Check no out-of-bounds speculative index and no read/write collision that changes an accepted value.
2. For every accepted stage/replay request, compare response valid, full address and epoch and data on the original cycle; compare readiness, error priority, queue occupancy/pop/push and counters every cycle. Deliberately vary invalid addresses and data; use targeted negative controls to show that stale responses, bad owners and omitted kill masking are detected. Check unowned speculative RAM data cannot feed a parser, FIFO, commit, or retry.
3. Inject reset/cancel and a wrong/stale response with both queued and outstanding reads, same-edge pop/issue and backpressure, and same-epoch restart. The local read port's speculative data is not an external transaction, but **real accepted physical writes and matching ACK debt remain governed by the existing external owner/drain logic**, never cleared merely because a read was speculative. Retain full-parent accepted bytes, canonical/hash/seal, error and drain checks and exact cycle checks where the contract requires them.
4. Run strict full RTL regressions and fresh placement/route using the same part, 125 MHz constraint, source manifest and comparable strategy. Verify actual mapped endpoints and all clock constraints; compare 100 MHz as applicable. Check the next worst endpoint, utilization, and RAM activity. Promote only if the intended contract passes and the complete routed design meets timing, not because this one reported path improved.
