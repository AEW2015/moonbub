## Preferred implementation

1. **Authenticated Windows test control.** One-time setup on`.47`: enable an SSH endpoint with a dedicated lab key/account or an authenticated allowlisted worker. Keep it running in the logged-in desktop session when capture/controller tests require that session. The controller at`.33` must launch and stop only the owned test process, obtain live PID/session/source port, collect logs and prove its remaining initial-wait window. No arbitrary process killing or password in chat. If enabling SSH needs elevation, prepare exact setup first and perform that one bootstrap explicitly.
2. **USB reboot/control driver.** Establish WinUSB on vendor interface0 only, preserving CDC1/2 and storage. First try read-only GET_INFO. A one-time driver binding may require administrative installation; the current process cannot silently perform it. A subsequent app may advertise Microsoft WINUSB OS descriptors for automatic binding, preserving the interface layout. This descriptor change is a separate firmware candidate, not part of V47's allocation comparison. An exact multi-byte CDC recovery command can be a fallback after one app update, rather than a dangerous accidental single-key reset.
3. **Qualify graceful recovery.** With host stopped and evidence frozen, invoke normal reboot, reacquire the same serial, verify reset reason/exact ELF/heap and stock boot FPGA state, then reload V027. Compare fresh CPU12 and network trials with the physical-cycle control. Do not force-release a native lease or redefine a software reset as full rail removal.
4. **App-only updates through software DFU.** Once vendor control works, reboot into the existing updater. Identify the installed updater and protocol first. Implement an application-only client: exact expected serial/Rev4, image/hash binding, source-size validation, erase-aligned factory partition limits`[0x100000,0x600000)`, backup/readback, bounded transfers/status/token checks, exact flashed-byte verification and reboot identity. Preserve updater, partition table, NVS and system_data. Interrupted-update recovery must be demonstrated before unattended repetition. Do not use an unverified generic whole-flash command or change partitions.
5. **One local orchestrator.** Acquire exclusive hardware lease → stop owned Windows sender → freeze/export old diagnostics → verified reboot/update if requested → boot identity/heap checks → JTAG exact BIT/DONE/USERCODE → USB/camera ready → remotely launch fresh pinned uploader → verify live process and remaining wait → arm once → collect both ends → validate checksums and matching presentations → stop at the first failure. Save exact sources/images/commands and results underC:/moon. Maximum attempts and durations are explicit; failures stop the state machine rather than trigger whole-run retries.
6. **Actual unattended power cycling.** A battery-powered handheld may stay on when USB power is cut. True off/on or recovery from a hung ESP32 requires a qualified external actuator: isolated Power/Volume− button contacts and, if needed, control of the battery/power path. A USB-controlled hub alone is not proven sufficient. No wiring changes or product purchase has been selected. Keep this hardware escape hatch separate from ordinary reboot qualification.
