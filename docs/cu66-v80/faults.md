# V80 actual-system fault and recovery campaign

`tb_system_fault.cpp` includes the unchanged V80 positive bench under a renamed entry point and exercises the actual mode-2 decoder, reference path, shared-P0 memory backend, SDRAM controller/model, CPU HUD endpoint, and continuous native LCD raster. It drives normal packet and external-abort inputs, with no internal force, memory seeding, reset between sources, or fault clearing. The frozen V79 health observer remains active on every evaluation.

The paced campaign has four attempts: accept a valid key; reject the next delta with a corrupted CRC; abort that delta after at least 64 observed physical canonical writes, coincident with an actual client-3 controller read acceptance; then retry the same valid delta with a deliberately dropped CPU commit acknowledgment. Each failed attempt must preserve the accepted reference, accepted HUD, and old physical front, and must complete another exact full old-front raster. The wrapper/prefetch path must drain and the raw bridge/controller must be observed idle before a later generation starts.

Abort selection happens before the next bench tick at a falling memory edge. The bench stops new HUD transfers and drains any outstanding HUD response, selects `trace_command_valid && client==3 && !write`, asserts the ordinary `abort_i` input, and reevaluates before the original tick captures handshakes. The selected controller request must remain valid after this reevaluation. The next tick must increment the independently observed actual client-3 acceptance count by exactly one. The campaign first searches for an outstanding receiver lookup at that coincidence, with a bounded 200,000-cycle search before accepting the next physical-read coincidence alone. `pending_lookup_at_abort` reports whether the combined case occurred; component cancellation tests cover other directed cases.

Failed attempts are counted as endpoint releases only on the actual terminal `aborted` indication. These increment the observer's released-endpoint accounting without invoking its successful-commit method or creating a fictitious raster obligation. Separate `SYSTEM_FAULT_ENDPOINT_RELEASE` rows and `aborted_endpoint_releases=2` distinguish them from the two successful commits. All four releases preserve their paced attempt ordinals; the valid retry uses ordinal 3 and generation 4.

Run with `python3 scripts/cu66-v80/run_system_fault.py`; immutable-binary replay uses `--skip-build`. The separate build path is `/build/v80-system-fault-prefetch2-tac2/`, compiled with one build job. Every attempt gets an immutable `system/faults/attempt-UTC-ID/` directory containing source hashes, mutable V80 source snapshots, build/run logs, command provenance, executable identity, and `results.json`, including failures. Complete frozen fixture and baseline pools remain pinned by SHA-256. Final stdout is JSON with status and results path.

The first two actual attempts passed the bad-CRC preservation/drain/full-raster case, then reached normal partial-candidate validation without arming abort. The fault bench had sampled the candidate bank immediately after admission, before parser allocation, so its canonical-write counter compared against a stale bank and stayed zero. The counter now samples the active candidate bank with each actual write, matching the V78 fault bench. An initial inference about the optional lookup-search bound was not established as the cause; that bound was shortened from three million to 200,000 cycles during investigation. Failed attempts remain at `system/faults/attempt-20261106T031720752546Z-0b347cd0/` and `system/faults/attempt-20261106T031910824036Z-670cbc7a/`, with source snapshots, logs, archived binaries, and build identities. Production sources were unchanged.

This is directed functional simulation, not physical fault injection or exhaustive fault coverage. CPU HUD/hash/control work has zero simulation cost. It does not establish live ESP32/Wi-Fi/QSPI behavior, target timing, CDC, fit, electrical behavior, or fatal scanout/cache recovery.


The third attempt, `system/faults/attempt-20261106T032047063739Z-e552a821/`, accepted the selected client-3 read coincident with external abort at cycle 4,791,483 after 18,584 canonical words, then reached actual terminal abort at cycle 4,791,520 with the backend drained. It failed an extra fault-bench expectation that aborted epochs have no completion pulse. The frozen V79 core deliberately pulses both `epoch_done` and `epoch_aborted` on aborted completion; the fault bench now requires exactly one of each and records their cycles. This correction changes no production behavior.

The final attempt passed: [`attempt-20261106T032224482435Z-1b8e74f4/results.json`](../../fpga/experiments/cu66-v80/system/faults/attempt-20261106T032224482435Z-1b8e74f4/results.json), status `PASS_ACTUAL_REJECT_ABORT_RETAIN_AND_RECOVER`, with two accepted sources, two rejected attempts, four admissions/releases, two explicitly aborted endpoint releases, zero underruns, and zero black lines. The partial abort coincided with actual client-3 read acceptance at cycle 4,791,483/address 542,904 after 18,584 canonical words. Both epoch termination pulses occurred once at cycle 4,791,508, followed by actual terminal abort at cycle 4,791,520. The accepted key reference/HUD and a complete old-front raster survived each fault. The same valid delta then recovered as generation 4 with full canonical/HUD verification, all 8,100 tiles filled/retired, 7,806 lookups, 32,400 physical prefetch reads, a complete correct raster, and two CPU commit calls confirming lost-ACK reconciliation. The bounded search did not observe an outstanding lookup at the abort/read coincidence (`pending_lookup_at_abort=0`), so that combined case remains covered only by component tests. Total runner wall time was 71.824 seconds under concurrent campaign load.
