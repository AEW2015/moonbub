# V80 integrated system observer and evidence runner

The V80 system bench forks V79's hardened observer and actual decode/display scoreboard. `monitor.hpp` and its nine synthetic unit checks in `monitor_tb.cpp` remain byte-identical to V79. The new `cu80_system_sim` top selects the existing production path with `PREFETCH_ENABLE=0` the integrated reference-prefetch path with `PREFETCH_ENABLE=1`, or the experimental shared-P0 release path with `PREFETCH_ENABLE=2`. Mode 2 releases P0 after a prefetch burst is snapshotted so candidate writes can overlap downstream stream consumption; mode 1 keeps the prior scheduling control. Independent native packet decoding supplies expected canonical planes and every displayed pixel. Actual FPGA decoding and SDRAM commands supply canonical storage, native HUD transfer/readback, and direct native LCD scanout. Expected memory is never seeded into the DUT.

Every `d.eval()` still passes through the frozen observer, including scheduled HDL events, all physical clocks, release waits, readiness waits, transactions, zero-time canonical peeks, and the final tail. The new prefetch fault output is also checked after every evaluation. There is one initialization reset per cohort, no per-source reset, and no per-source fault clear. Original physical timing is retained: 10,000 ps memory period, read rising edge at 2,750 ps and falling edge at 7,750 ps, and 17,029 ps pixel half-period. The original initial release is memory cycle 108. Fixed30 releases remain `108 + floor(ordinal × 100000000 / 30)` and are never shifted to hide readiness waiting.

Each receiver commit ACK creates one obligation to complete that generation's correct 480×800 raster within 10,000,000 memory cycles (100 ms). An already completed raster satisfies it immediately; ACK retry cannot extend its deadline. Every source must have a distinct full raster with all ordered rows, columns, border pixels, and one generation. Sticky LCD errors, memory errors, and underruns fail immediately in every phase. Monitoring continues at least 3,500,000 cycles after the last ACK and until all raster obligations are met. The frozen watchdog is `108 + requested_frames × 110000000 + 10000000` cycles. These conservative functional liveness checks remain separate from strict packet-complete-to-validation `<10 ms` and packet-complete-to-ACK serial30 budgets.

The eight `base{0,1}_tile{0,1}_aux{0,1}_cycles` bins and sixteen receiver-stage bins each independently partition every transaction cycle. These describe occupancy and overlap, without claiming that subtraction identifies a critical path. Canonical writes and HUD writes must retain exactly 280,320 bus words and 35,040 BL8 commands per source; HUD write and readback each use 2,640 BL8 requests. The second source retries a deliberately dropped CPU commit acknowledgment, preserving exactly-once commit checks.

`SYSTEM_PREFETCH` records the core's epoch identity and retained per-epoch counters. Completion and abort are one-cycle pulses: the bench samples each once after every memory rising edge and records counts/cycles by epoch generation. A delta requires exactly one completion event strictly before commit ACK and no abort event; instantaneous levels are reported separately. Counters reset on a delta epoch, rather than every source, so they are interpreted with `prefetch_epoch_generation`; they are never blindly differenced across epochs. Baseline diagnostics remain zero. Key sources launch no epoch and leave retained epoch counters unchanged. Each optimized delta must complete the matching generation without fault or abort, with 32,400 logical BL8 reads, 259,200 words, 8,100 filled and retired tiles, 7,806 receiver lookups, and 294 tiles retired without lookup. The read count covers all 8,100 tiles × four BL8 reads, including unused tiles.

`SYSTEM_COMMANDS` independently counts actual controller accepts by client: 0 is tile writes or legacy reference reads, 1 is HUD, 2 is LCD, and 3 is reference prefetch. Its physical reads remain distinct from logical core requests; cache hits can reduce physical commands. All four receiver tile-event streams are checked per generation, bank, plane, and tile index for bounds, duplicates, request/response pairing, and write/completion pairing. Every tile must be written and completed exactly once. Actual reference request/response events number zero for keys and 7,806 for deltas. Prefetch fill counter transitions are checked independently. No waveform is emitted by default. `SYSTEM_STREAM` reports the per-transaction differences of three globally reset cumulative backend counters: candidate wait cycles, idle candidate wait cycles, and accepted candidate writes. Its numeric `mode` records 0/1/2; baseline counters must remain zero. These are observations of scheduling, without implying a latency or throughput gain.

Run the observer proof and build one system variant at a time:

```sh
python3 scripts/cu66-v80/run_monitor.py
python3 scripts/cu66-v80/run_system.py --prefetch 0 --cohort 0 --frames 2 --mode fixed30 --tac 2
python3 scripts/cu66-v80/run_system.py --prefetch 1 --cohort 0 --frames 2 --mode fixed30 --tac 2
python3 scripts/cu66-v80/run_system.py --variant prefetch --cohort 1 --frames full --mode fixed30 --tac 2 --skip-build
```

`--frames` accepts 2, 4, 30, or full; cohorts 0–3, paced/fixed30, and TAC2/TAC7 are supported. `--variant baseline/prefetch/overlap` aliases `--prefetch 0/1/2`. Omitted variant selects prefetch. Binary directories are distinct `/build/v80-system-prefetchN-tacT/`, with top executable `Vcu80_system_sim`. Each `build-prefetchN-tacT.json` records source hashes, binary SHA-256, variant/TAC, and build commands. An exclusive per-variant lock rejects concurrent builds. `--skip-build` performs no build and requires an unchanged source identity and executable digest. Existing build records are immutable; rebuilds require explicitly archiving the prior identity.

Every invocation creates a unique attempt directory under `system/cohortN-framesCOUNT-MODE-prefetchN-tacT/`. Before building or running, it snapshots mutable V80 code, the runner, and the source specification into `sources.tar.gz`. `source-manifest.json` hashes the complete RTL/include/native-header/native-fixture pool, including all finite cohort packets; frozen inputs resolve from the unchanged repository and baseline rather than duplicated packet archives. Source identity is checked after snapshotting, after building, and after a successful run. Every command retains argv, digest, exit status, timeout, and elapsed time. Failed attempts keep their logs, source snapshot, and `results.json`. Runtime has an in-container timeout of `600 + requested_frames × 120` seconds with a 10-second kill grace and a longer host timeout. Final successful stdout is JSON containing `status` and `results_path` for orchestration.

Use `--trace` for a two- or four-source run, or repeat `--trace-frame ORDINAL` to select at most four zero-based source ordinals from a longer run. This emits bounded event CSV, capped at two million records, then deterministic gzip (`mtime=0`); raw SHA-256, raw byte count, compressed SHA-256, and event counts are retained in `results.json`, including failed attempts. Columns are cycle, simulation ps, bench source generation, event, owner generation, client, write flag, physical address, bank, plane, and tile index. Controller and receiver events sample before the memory rising edge at `t+5000`, using cycle `cycles+1`; filled tiles are observed after that edge with the same timestamp. Physical command ownership is deliberately generation 0 because the controller does not expose owner identity; `frame_generation` is bench context, not inferred ownership. Unused fields are zero. Fill bank is the active reference bank and plane/index derive from the core's checked sequential fill ordinal. A trace can contain LCD commands outside the profiled transaction during release/readiness/tail; the aggregate `SYSTEM_COMMANDS` counters cover transaction cycles only.

The nine observer checks use synthetic outputs and demonstrate verification behavior only: `observer_unit_only=1`, `hardware_fault_injection=0`. Native HUD CPU/hash/control executes at zero simulation time. All results remain finite functional simulation, with no live ESP32/Wi-Fi/QSPI, physical 30 fps, target validated-under-10ms, target fit/Fmax/CDC, or electrical timing proof.
