# V82 incremental content commitment

This is an explicitly negotiated new application profile, `CU66-V82-CONTENT-SHA256-TREE-2`, capability `cu66-v82-content-tree-sha256-v2`. Its content root and frame seal are SHA-256 commitments, **not a MAC or proof of sender identity**. They have no old CU66 canonical-tag semantics. Original CU66 flat plane-raster SHA-256 validation remains an independent oracle in the native/export and integrated execution evidence. Native pixel quality, quantization, packets, and HUD reconstruction stay unchanged.

`python3 scripts/cu66-v82/prototype_commitment.py --native` writes a new immutable attempt directory containing its exact source snapshot, JSON report, frame work log, and SHA-256 manifest. Earlier TREE-1 attempts retain their earlier verbose serialization and cannot be substituted for the TREE-2 result.

## Compact binary serialization

All integers are unsigned, big endian. `D` is the ten bytes `CU66V82C2\0`. The constant context is `SHA256(JSON)` of the configured profile ID, geometry `(720,480,5400,1350,1350)`, and leaf tile granularity, using sorted keys and no whitespace. This descriptor is prepared by configuration software; the proposed binary datapath does not parse JSON. Computing the context is explicitly reported once per configuration, including SHA padding blocks. No prefix midstate reuse is assumed.

| Hash | Message |
|---|---|
| Real leaf | `D || L\0 || context[32] || plane:u8 || plane_local_start:u32 || count:u16 || count*64 decoded tile bytes` |
| Padded leaf | `D || E\0 || context[32] || leaf_index:u32 || padded_leaf_count:u32` |
| Internal | `D || N\0 || level:u16 || level_local_index:u32 || left[32] || right[32]` |
| Frame seal | `D || S\0 || context[32] || fid:u32 || refid:u32 || key:u8 || generation:u64 || previous_accepted_root[32] || HUD_digest[32] || content_root[32]` |

Real leaves group 1, 4, 16, or 64 contiguous tiles **within each plane**, with shortened final groups. Y, U, then V groups occupy a single tree, padded to a power of two using explicit domain-separated empty leaves. A real leaf prefix is 51 bytes; a 64-byte tile therefore costs two SHA-256 compression blocks. Internal messages are 82 bytes (two blocks), seals 157 bytes (three blocks), and empty leaves 52 bytes (one block). Compression blocks always use `ceil((message_length + 9)/64)`, including mandatory SHA padding. The header binds geometry, profile and granularity through the context. Leaf positions and counts are committed directly; tree levels and positions are committed internally.

A delta seal binds the last accepted content root, not a speculative candidate. A key uses an all-zero previous-root sentinel and freshly hashes all real leaves, padded leaves and internal nodes. Even keys must advance accepted fid and generation; rewinding requires explicit reset. The native decoded HUD digest is consumed as an existing 32-byte digest, without hashing that digest again under a raw-HUD label.

## Semantics and atomic acceptance

The conservative COPY mask comes only from visible delta tiles whose encoded quantized residual coefficients are all zero. Byte equality is used only in the explicitly labeled optimistic comparison. Hidden tiles are generated CONST128; they are distinct from COPY and consume no pixel reference bytes. A delta leaf can reuse its digest only when every tile is semantic COPY or a CONST128 tile whose accepted value was already CONST128. Any other tile forces a real leaf hash, even if its bytes happen to remain equal. Ancestors are hashed only if a child digest actually changes. Equality comparisons and reuse decision dependencies propagate through unchanged subtrees in the scheduling DAG.

The independent host `full()` rebuild starts with actual current decoded bytes every frame, without incremental nodes or COPY masks, and computes both the content root and frame seal. The protocol decoder reconstructs COPY from its last accepted reference, CONST from generated bytes, and DATA from the exact 64-byte payload; its independently rebuilt result must match the expected host root and seal. Candidate state remains separate until acceptance. Abort and malformed partial transactions discard candidate state, and late commits are rejected using an internal revision plus accepted root/seal. Repeated ACK of the already accepted seal is idempotent.

Synthetic tests cover keys and reset, missing opt-in and reference, stale reference/key/fid/generation, cross-profile/capability/geometry mismatch, false COPY on a changed tile, order/index/duplicate corruption, payload/HUD/root/seal tampering, truncation, CONST payload rejection, abort and partial rollback, late ACK/commit, independent full-tree equality, fresh padded key trees, and stopping propagation when a recomputed leaf digest remains equal.

## Storage and timing scope

| Tiles per leaf | Real leaves | Padded leaves L | Two full tree buffers | Trees + 6,075-byte V81 maps |
|---:|---:|---:|---:|---:|
| 1 | 8,100 | 8,192 | 1,048,512 B | 1,054,587 B |
| 4 | 2,026 | 2,048 | 262,080 B | 268,155 B |
| 16 | 508 | 512 | 65,472 B | 71,547 B |
| 64 | 129 | 256 | 32,704 B | 38,779 B |

Both accepted and candidate trees are priced as `2*(2*L-1)*32` bytes. The constant context needs another 32 bytes. SHA lane state, scheduling/control metadata, candidate flags, and existing pixel storage are additional and are not claimed to fit in BRAM. The Python reference stores decoded pixels for semantic verification; the tree metadata figures do not erase pixel-reference or candidate-storage requirements.

The DAG reports exact message lengths and compression-block counts, followed by idealized nonpreemptive schedules with one, two, or four identical hash lanes. Each lane assumes 64 rounds per block at one round per cycle, with all hash input bytes available at time zero. These schedules do not validate decoding, DMA/payload availability, Fmax, RTL feasibility, throughput, or a 30-fps system. Integrated reference-read, execution, and memory costs are reported separately by the root execution model.

## Python interface

Load `scripts/cu66-v82/prototype_commitment.py` and instantiate `CommitmentTree(granularity=g)`. `plan(frame, copy_mask)` returns `root` and `seal` as bytes, `recomputed_groups` with global tile indices and copied/CONST subsets, the hash `jobs` DAG with lengths/blocks/cycles, `lane_cycles`, and memory figures. Call `full(frame)` before `commit(plan)` to independently validate. Flat native `tiles` or nested `planes` are accepted. Use `hidden_mask`/`const_mask`, `hud_sha256` hex or `hud_digest` bytes, explicit new profile/capability, and generation. `Decoder` provides negotiated stage/abort/accept/reset transactions.
