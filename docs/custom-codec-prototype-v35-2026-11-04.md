# V35: exact map reuse and transform-aligned visible-error experiments

This iteration has one clear exact-performance improvement: validated reuse of
already-paid motion maps makes HM34 encoding **13.22× faster as a component**,
with all tested wire bytes and pixels unchanged. Transform-aligned opaque-HUD
masking improves the previous byte/error trade-off. However, even a strict
same-frame visible-error guard does not eliminate the small quality regression
against an independent causal control history. **HEVC/AV1 compression parity
and physical 30 fps remain unproved.**

Geometry remains 720×480 coded / 720×405 active with exact 21,120-word RGB565
HUD. The two short retained Mass Effect windows are reused, not held-out content.
Rates at 30 decisions/second are nominal byte arithmetic. No native firmware,
bitstream or remote hardware is modified; JPEG and v20 remain unchanged.

## Exact HM34 encoder reuse

[The reuse implementation](../experiments/python-game-reuse-v35-study/README.md)
accepts cached parent32 and child16 GM27 payloads already generated by source
analysis. It independently syntax-decodes them, checks exact field equality and
uses vectorized canonical cost planning to verify mode, default and Rice ties.
Valid but nonminimal caches are rejected rather than changing old HM34 output.
Uncached and partial-cache calls retain the frozen encoder fallback.

The new encoder computes every candidate's complete size, including all Rice
trials, masks, deltas, padding and CRC overhead, then serializes only the winner.
It does not remove losing rate decisions or trust arbitrary cached lengths.
Production code does not patch old modules. A scoped behavioral test makes the
frozen map encoder fail if accidentally invoked on the cached path.

| Paired component metric | Frozen implementation | Reuse implementation |
| --- | ---: | ---: |
| Mean of per-field paired medians | 44.0973 ms | 3.33539 ms |
| HM34 candidate sizes evaluated | 3 | 3 |
| HM34 candidates serialized | 3 | 1 |

The measured ratio is **13.22×**, saving 40.76 ms/component on this host. Three
paired repetitions alternate order per field. Cache validation, setup, complete
cost planning, winner bit emission, sealing and info construction are paid.
Original parent/child map generation remains explicitly recorded as already-paid
source analysis. This is not a 13.22× sender speedup, nor a subtraction from an
older whole-policy timing run with different load.

All **184 motion components and 368 GM34 frame rewraps are byte-identical** to
v34. The independent verifier imports no reuse encoder, checks all component
syntax and source hashes, replays 192 accepted reference frames and decodes all
368 variants against their causal references/pixel tags. Decoder math, memory
traffic, wire syntax and FPGA work are unchanged. Seven tests cover all selectable
canonical modes, partial caches/geometry, empty refinements, stable complete-size
ties, invalid/mismatched/nonminimal caches and behavioral no-reencode validation.

## Transform-aligned hidden-source formation

[Core8 masking](../experiments/python-game-aligned-v35-study/README.md) replaces
only complete aligned 8×8 Y/Cb/Cr blocks whose entire reconstructed RGB support is
hidden by the exact opaque HUD. Chroma support comes from independent scalar
enumeration of the frozen right/below upsampler, including clamping. A doubled
chroma rectangle is insufficient; the support also extends above/left.

Integral coverage of the rectangle union handles odd bounds, overlap and partial
edges. Partial transform blocks are preserved. The fixed profile masks 256 luma
and 19 blocks on each chroma plane: 18,816 stores, with owned int16 planes occupying
1,036,800 bytes. Coverage/integral workspaces are additional host temporaries;
none of this image allocation is assigned to the ESP32 transport gateway.

All 96 inputs preserve **exact RGB8 outside the HUD** and RGB565 after overlay
before coding. Scalar tests check accepted and rejected tile footprints. This
does not establish equal quality after lossy coding or changed reference history.

| RAW, independent causal history | Original complete bytes | Core8 bytes | Original MSE | Core8 MSE |
| --- | ---: | ---: | ---: | ---: |
| Primary | 441,224 | 422,312 | 14.386886 | 14.391345 |
| Complex | 1,068,678 | 1,036,928 | 26.303889 | 26.349431 |

RAW bytes fall **4.2863% / 2.9710%**, with MSE increases of **0.0310% / 0.1731%**.
This substantially reduces the added error of v34's boundary-preserving mask,
but does not meet the quality-neutral goal. Maximum packets are 22,484 / 41,155
bytes, below the respective original control peaks 23,321 / 43,106.

All 376 candidates and 96 accepted CP34/HX33/JA34 frames are actual archived
packets. Source-preparation/equivalence work is separately recorded; RAW policy
means 227.11 / 320.52 ms exclude it. A postcampaign mask-only measurement averages
4.438 ms. Preencoded HUD, fixture conversion, archive I/O, network/display and
native device work are excluded as documented. These are not 30 fps measurements.

Twelve fresh standard-codec runs apply the same original/core8 processing,
encoder settings, actual HX33 + 60-byte binding and once-only extradata. All 576
AUs decode with PTS/DTS 0..47, keys 0/24 and immediate output rather than flush-only
frames. Weaker complex brackets that fail custom quality remain in the evidence.

## Guarded masking on the current reference

[The guarded controller](../experiments/python-game-controller-v35-study/README.md)
encodes both original and core8 source against the policy's own currently
accepted reference. Every original and masked zero/half32 incumbent/band trial
is paid and retained. The full fitting original-source winner is the shadow.
Masked admission requires strictly fewer complete bytes and active RGB SSE no
higher than that shadow; ties retain original control. Metrics always compare
with the original RGB source after exact HUD overlay.

| 48-frame window | Policy | Actual complete bytes | Active MSE | Paid policy ms/frame |
| --- | --- | ---: | ---: | ---: |
| Primary | Original control | 441,224 | 14.386886 | 229.49 |
| Primary | Guarded core8 | 422,128 | 14.393638 | 477.87 |
| Complex | Original control | 1,068,678 | 26.303889 | 327.70 |
| Complex | Guarded core8 | 1,035,638 | 26.349043 | 667.53 |

Guarded bytes fall **4.3280% / 3.0917%**, but mean MSE still rises **0.04694% /
0.17166%** against the independent control. All 96 frames select masked source
and pass their local guards. The original-source shadows on those changed
references cost **497,449 / 1,187,655 bytes**; they are not the standalone control
budgets. Comparing only against those larger shadows would inflate the gain.

The experiment does **not** prove quality-neutral streaming. Hidden reference
content influences future motion and reconstruction, even though each source
mask is precodec-invisible and each current-frame guard passes. The issue is
reference semantics, not simply a missing rectangle-boundary check.

All 192 accepted frames, 1,128 candidate frames and 4,055,040 HUD words replay.
The 96 original control packets reproduce v34 exactly. Mask work averages
4.61 / 4.90 ms and is included in the guarded policy clocks, along with every
analysis, shared-pair call once, RGB quality check, binding and selection.
Precodec equality proof, fixture reads/conversion, preencoded HUD, archive I/O,
receiver and network/display are separately excluded. The guard roughly doubles
host policy work. It is a research qualification mechanism, not a useful default.

## Fresh native comparison on the exact selected source trace

Four additional native runs consume exactly the original/core8 choice accepted
by the guarded controller, including per-frame input hashes. Every choice in
this run is core8, so the resulting anchors also reproduce the RAW study's
processed-input anchors. These 192 additional AUs have the same low-delay
PTS/DTS/key/output checks. All source/HUD/extradata/binding bytes are accounted.

| Guarded-trace nominal complete Mbps at30 | Custom | HEVC | AV1 |
| --- | ---: | ---: | ---: |
| Primary | 2.110640 | 1.197535 | 1.113240 |
| Primary active MSE | 14.393638 | 11.356621 | 12.471908 |
| Complex | 5.178190 | 3.041230 | 2.984720 |
| Complex active MSE | 26.349043 | 21.799157 | 20.025998 |

The sampled HEVC q32/q28 and AV1 q48/q38 points still have fewer bytes and lower
mean MSE and fit every complete frame cap. Native binding is cost accounting,
not a Gamebub standards decoder or native CP34 implementation. This is not
matched-quality BD-rate, perceptual equivalence, optimal standards encoding or
a resource-constrained FPGA-decoder comparison. Same-source processing and exact
HUD credit cannot be withheld from the standard codecs.

## Next: a codec-domain occlusion experiment, not another quality claim

1. Prototype a **canonical hidden-reference profile** as a separate hypothesis.
   Both its control and skip variants would normalize fully hidden, support-safe
   reference tiles identically after reconstruction. With the same predictor and
   visible coefficients, omit hidden residuals and prove equality of the entire
   normalized reference plus visible output over the whole causal chain. This
   would need an explicit new profile/tag contract; it is not implemented here.
2. Compare that new canonical control against the original profile separately.
   Equality within a new profile would not prove unchanged quality versus the
   old reference semantics. Preserve all losing trials, source metrics and
   peak/temporal error. Add longer unseen gameplay and boundary-heavy cases.
3. Port the exact cached-map encoder into native host code and measure complete
   sender service while retaining byte identity. Keep initial map-generation,
   HUD preparation and transport costs visible; do not multiply component gains.
4. Carry independent malformed/cached-map/frame goldens into native and FPGA
   work. Quantify whole entropy/dequant/inverse/prediction/HUD service, memory
   arbitration, reset/ACK/retry/publication fences and ESP32 DMA/Wi-Fi/QSPI limits.
   A fully measured system is required to establish physical 30 fps or an
   application/hardware advantage over a standards implementation.

The mask and reuse experiments have not been combined into one timed sender.
The original JPEG and v20 hardware branches remain unchanged. Current evidence
supports an exact host optimization and better source-formation trade-offs,
not HEVC/AV1 parity or a quality-neutral new deployment mode.

## Reproduction

```sh
python experiments/verify_prototype_v35.py
```

The manifest pins frozen v34 files, new source/producer code, actual custom and
native packets, source hashes, test logs and replay helpers. The independent
audit reconciles cost groups, guards, separate accepted histories, source traces,
actual bytes/caps/error and fair native points. The study uses the configured
Python/NumPy/PyAV environment and retained inputs; no original video download
or attached Gamebub hardware is required for replay.

There are **18 focused passing tests**, 288 accepted causal custom frames,
1,504 causal candidate frames and 768 fresh native AU decodes. The exact-reuse
study separately verifies 184 components and 368 preserved frame variants;
those are not additional new causal content or a complete-sender timing result.
