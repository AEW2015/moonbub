# Optional compact packet histories: design only

Recommendation: execute the selected v31 physical comparison FIRST, with the same savedclip/hash/offset, pacing, input-onlyAV, build50, overlap and32slots. V31 has not yet measured its context-only hot snapshot/per-Kind loss changes on hardware. Introducing a second recorder design now would confound that comparison. The proposal below is a possible later opt-in diagnostic candidate, not implemented source, a speed claim, an installation recommendation or evidence that tracing caused drops. Sealed parents remain unchanged.

## What the actual code establishes

Pinned v31 streaming/mod.rs965 stamps socket return after matching configured hostIP. Its producer caches a parsed frame/offset/queue context before moving the DMA packet into producer.submit; Enqueue is then published after successful submit. The saved enqueue time is a PRE-operation observation, not atomic channel acceptance. A fast consumer can dequeue/fail before the producer publishes its Enqueue. A new hook must cache header data before submit and never inspect a moved/recycled DMA buffer afterward.

Header::capture_us is already parsed as fullu64 (protocol.rs76,94). Receiver::active_identity returns the full Header plus expected offset (169). Diagnostic Position/Context, Raw and RawFailure omit numeric capture_us; equal frame/offset alone cannot distinguish replayed identities. Socket arrival_us already travels with the actual RxPacket. It is a local ESP timer observation, not an RF/MAC arrival timestamp.

Consumer session mod.rs1246 records Dequeue before possible peer reset;1271 resamples active identity immediately before accept. The observer must retain BOTH boundary meanings or clearly label the selected preaccept context. The Failure hook1365 is suppressed when that offending ID was already counted as dropped. A new per-packet outcome update must be OUTSIDE that suppression without changing logs, drop accounting or Receiver behavior. Existing failure detail lower9bits/bit12 includes Sequence, noactive and staleSOF; do not trigger only the first offset mismatch64. Recycle/Complete1417..19 occur after actual recycle; fatal BufferDrop/Complete1401..04 deliberately preserve the existing nonrecycle path. Background Transfer291 is real timed forwarding after packet completion; it must remain represented, not relabelled idle.

V31 uses a shared try-lock for salient records; it retains96 Raw entries and first32 Failure/tails. Routine phases are single-consumer atomic-only. The hot context read excludes full maxima. The actual target Trace is8272B. The saved v30 repeat had2085record losses, no phase loss and no local queue drop; its missing10240 identity was absent only from a lossy retained window. Numeric capture_us and a separate loss-free socket history were unavailable. V31's forthcoming per-Kind physical losses may narrow the next need before this redesign.

## Smallest useful replacement, not an extra full recorder

Keep the existing AtomicPhase versioned context, all16 full-u64 maxima, manual-seal/arm writer fence, first-overflow absolute-time latch, global counters and first32 auxiliary Failure/tails. Do not copy maxima on packet hooks. Replace ONLY the96-entry salient ring backing in a separate opt-in diagnostic candidate with two SINGLE-WRITER histories. Initial state remains disarmed. Do not retain both old/new full rings or introduce a worker/heap allocation. A new versioned export is required; old v1/v2 exports/collector acceptance remain preserved separately. The original96-event ring is no longer supplied by that optional new backend; this is an explicit diagnostic schema change, not a hidden phase-proof removal.

Producer:64records, one per expected-host socket-return datagram. Every record carries outcome (submitaccepted/no-buffer/full/disconnected/malformed), sourceport, full incomingframe/capture_us/offset, actual local socket-return time, local journal-observation time, sampled queue occupancy and coherent consumer activeframe/expected/phase/phase-since when available. Malformed identity has explicit invalid bits; zero frame/capture are legal, not sentinels. Nonmatching-host datagrams/socket errors require separate counters so continuity scope stays precise. This journal runs before the old auxiliary diagnostic mutex. A later legacy failure-table lock loss cannot erase its primary entry.

Consumer:40records, one per dequeued packet, updated in place by the SAME consumer at preaccept, Failure and Complete. Keep full incoming and preaccept active capture_us, frame/off, queue snapshot, received_us, dequeue time, failure phase/since, full-consumer/lock/QSPI durations and lifecycle flags. Complete means after actual recycle or explicit fatal drop; an unfinished record stays incomplete. A local consumer ordinal selects its row and must match before any update, preventing a stale Complete from altering a reused row. Rare background Transfer gets its own row with identity invalid, and counts against the bounded horizon. Failure's original context/phase must survive its later Complete update. No new RxPacket field or TLS allocation is needed: the private single-consumer backend keeps its current row ordinal; existing scoped hooks prevent UI/local/benchmark calls from impersonating this writer. Unexpected nesting/wrong writer must reject/count, not take another producer role.

Consumer full elapsed/lock/QSPI sums may retain the current explicit saturatingu32 representation with clipping flags; all absolute clocks/capture identities remain fullu64. Incoming/active frame and offsets remain fullu32. Phase/queue packing changes no accepted protocol or32-slot capacity. Raw queue values outside the implemented range clear validity instead of becoming a fake validzero.

Producer ordinary rows do not contain active capture_us: the existing AtomicPhase context cannot supply it. They contain coherent activeframe/expected/phase with that limitation. Consumer preaccept rows DO include active capture_us. Do not enlarge/change AtomicPhase silently or infer active capture from an equal frame ID. A producer-origin trigger therefore marks active-capture unavailable unless separately proven. Exact producer?consumer association uses full incoming frame/capture/off + actual RxPacket received_us/sourceport; duplicate equal tuples within one microsecond are ambiguous, not invented unique tokens. Adding a propagated producer token would be a separate queue-metadata/SRAM change and is not proposed here.

## Nonblocking publication and positive seal

Every payload word is AtomicU32. Single writer stores slot commit=0, writes all payload words, then publishes a fresh nonzero revision. Consumer in-place Failure/Complete updates MUST publish a NEW revision, not the same allocation ordinal; otherwise an entire update between reader checks would be an ABA bug. A single-consumer monotonic revision counter uses the reserved control words and stops before wrap. Initially use SeqCst for every commit/payload operation, matching the existing proof style; do not weaken to relaxed-data seqlock without a separate memory-model proof. A reader attempts once: nonzero commit, copy words, same commit again. Any change/zero returns unavailable. There is no loop/spin, unsafe aliasing or data race. Allocation row ordinals remain separate nonzero monotonic counters. They are derived for export from the positively sealed immutable head/length/slot mapping, so an additional per-row ordinal word is unnecessary. A consumer update token is checked against that current retained ordinal range and slot mapping before updating; stale/evicted tokens reject/count. Live public reads are forbidden. Stop capture before either revision OR allocation-ordinal reuse/wrap; exhaustion clears validity. A sequence hole is a diagnostic loss, never a packet-drop count. Even though uncontended single writers should not lose to one another, reentry/admission/epoch/invalid-state/publish failures must increment per-hook counters.

Register EVERY writer before its first armed lookup, as in v31. Arm disarms SeqCst, requires zero admitted writers, resets/publishes a new epoch and only then re-arms. External caller quiescence remains mandatory. ManualF disarms, waits by returningfalse/retry until admitted writers drain, closes phase maxima and seals every history/counter/trigger. It does not busywait. After successful manualseal, repeatedF and pagedreads cannot change bytes or counters. Read requires this positive seal and stable epoch; no concurrent hot export. Auto window freeze stops new rows but allows the retained trigger row's late Complete and auxiliary aggregates until manualseal. An incomplete tail stays explicitly invalid.

No new diagnostics acquire Device, a channel/queue mutex or the legacy trace mutex on the primary producer/consumer write. They perform bounded header-copy/atomic work. That is a bounded operation-count proposal, not a speed/latency or scheduling-neutrality measurement. Extra atomics and phase snapshots can still perturb timing; disarmed/armed comparison and actual frames are required.

## Trigger boundaries and continuity

Explicit proposed policy is AnyFirst: first claimed Sequence/noactive/stale-SOF Failure OR QueueOverflow, whichever wins the atomic latch. Keep independent first-overflow time even if primary row/trigger context is unavailable. Export cause/origin/fullESPtime and coherence. CAS winner is the first PUBLISHED claim, not a proof of earliest cross-core event clock. A delayed earlier call may have an earlier timestamp. If Sequence must remain primary after an earlier overflow, that is a different policy/two-window requirement and needs explicit approval; this design cannot promise all first windows simultaneously.

Each writer retains at most16 NEW post-trigger-observed rows; updating a retained row's Complete does not consume a post slot. Producer64 then normally retains48prior/16post packets; consumer40 normally retains23prior+trigger+16post entries. Background Transfers shorten consumer packet horizon. Each writer starts its post budget when it observes the trigger; in-flight cross-core boundary races are flagged. A stopped/descheduled writer may never produce16post rows: manualseal records incomplete posthistory rather than fabricating it. Bank heads/freeze cursors and first/last ordinals are exported independently; there is no invented global channel order.

Counters distinguish attempted/published/overwritten/rejected/suppressed-after-auto-freeze and per-hook/Kind losses, plus all existing failure-capacity/tail-ambiguity/clipping/phase validity. Saturation/wrap invalidates continuity. Freeze does not erase global aggregates or silently count suppression as a packetdrop. Auxiliary32Failure tails preserve their existing semantics; later failures outside the compact frozen histories still lack numeric capture_us in that old table. Export that limit explicitly.

Actual RxPump join result and queue occupancy BEFORE teardown must be observed without changing existing join/drop behavior. STOP may discard queued, unprocessed packets; consumerquiet alone does not prove queue drain. An end-of-capture flag must distinguish joined/empty versus pending/discarded/unknown. This is observational status, not a new ownership/drain certificate.

Absence can be stated only for an explicitly bounded, contiguous, valid-identity interval of expected-host SOCKET RETURNS with matching captureepoch/sourceport, no holes/wrap/unknown entries and valid end boundary. Even then say no parsed matching identity was observed at that socket-return layer. Do not say it never arrived overRF, identify a network loss cause, or infer an unseen predecessor from expected_offset. Host outboundpcap and device local timer domains cannot be subtracted. Numeric capture_us is an opaque sender identity; use equality and packet ordering within each clock domain. Positive producer/consumer matches and local dequeue-minus-received_us are useful; ambiguous duplicate tuples remain ambiguous.

## Required tests/gates before implementation adoption

1. Exact array/metadata layout, max legal IDs/capture0/u64MAX, sourceport/queue validity, clipping and hard target aggregate9216B cap; no hidden RxPacket/TLS/heap growth.
2. Forced pause at every producer/consumer payload word and commit boundary; reader returns a coherent row or unavailable, never mixed halves. Reader is single attempt. Force a complete consumer update between the two commit reads: NEW revision must prevent ABA; validate sealed head-to-ordinal mapping and reject evicted/stale tokens. Reject wrongwriter/reentry and count it.
3. Writer admitted before first armed check, rearmABA, in-flight arm/reset, concurrent Phase and manualF, repeatedF idempotence, immutable allpage export after seal. Reuse v31 SC fence regressions.
4. Producer receives N datagrams with successful/full/no-slot/disconnected/malformed outcomes: exactlyN eligible ordinals or explicit holes; post-submit publication may follow consumer dequeue and must not alter the channel call order.
5. Prepeer-reset Dequeue and actual preaccept context, all actual Sequence/noactive/staleSOF outcomes including suppressed duplicate-frame Failure logs, full capture IDs and crossframe/reused-ID ambiguity.
6. Failure?abort/log/feedback/yield?actualRecycle/BufferDrop?Complete; late triggerComplete remains available after auto-freeze. Lost/stale/torn Complete cannot update another ordinal. Background Transfer identities stay invalid.
7. Concurrent firstSequence/QueueOverflow/noactive claims, independent overflowclock, exact16 per-writer post NEW rows, boundaryrace/incompletepost flags and saturation before ordinalABA.
8. Ringwrap and overwritten-range classification: absencechecker refuses any hole, malformed/unknown identity, resetepoch, wrap, unjoined/nonemptySTOP or mismatched multi-page record. Duplicate equal tuples cannot become unique matches.
9. Full16phase maxima/context coherence retained from v31, no perphase journal flood and no hot maxima collection; phase-snapshotUNKNOWN never passes as validzero.
10. Versioned compact collector rejects mixed/unknown schemas and missing/inconsistent ordinals/pages; existing savedv1/v2 exports stillpass. One<=192B payload/USBcommand, copied row only, quiet/manualsealed export.
11. Actualtarget check/release/UF2, config/ABI unchanged, aggregateSRAM and producer/consumer/USB frames/heap review, then root-approved matched physical test. Preserve build50/32queue/wire/PS/pacing/sender. No automatic programming or causal performance claim.
