# Python Game Bub v12 evidence audit

This independent standard-library audit covers the rate-motion, refresh-policy, sparse inverse-transform, and memoization studies. It reads retained JSON and pinned source/test artifacts only; it does not rerun benchmark or video workloads.

## Findings

- **Sparse inverse bypass:** 120 source-frame records cover two 720×480 clips. These contain 92 distinct RGB content hashes (32 in the combat clip, 60 in the second clip). All 120 baseline/fast RGB, reconstructed-YUV, and RGB565 checks match exactly. Across the rows, 972,000 inverse blocks partition into zero, DC-only, and general inverse work; bypass counts equal zero plus DC-only counts. The fast path preserves GM01/HG01 packet hashes and bytes; it makes no packet-byte savings claim. Whole-decoder calls and core reconstruction calls are reported as the study records them. Host timing is not physical decoder timing.
- **Rate-motion selection:** 462 profile decisions cover 154 source-frame IDs and 114 distinct RGB hashes: 120 temporal real, 16 held-out real, and 18 synthetic source-frame decisions. Across GM-only, block-motion-only, and actual-rate runs, 453 decisions are admitted and 9 are rejected. The selector evaluates 308 candidates, including 157 losing candidates with explicit service costs totaling about 5.51 seconds; all selector candidate service totals about 9.10 seconds. The 154 paired comparisons use the same canonical reference and report candidate packet/control matches. GM and block-motion active MSE differs on 135 comparisons despite fixed quantization. Complete packet bytes equal inner bytes plus recorded envelope header/CRC for every actual-rate row. The experiment uses no future frames or quality oracle; its host measurements do not establish device performance.
- **Refresh replay:** 17 separate 60-capture runs sum to 1,020 capture events, 853 strict presentations, and 886 eventual presentations. These counts are run totals, not unique frames. Timestamp-derived strict counts match stored values; every run drains outstanding work. All admitted complete packets fit the 49,152-byte cap. Across runs, measured encode/decode wall totals are about 20,981/21,069 ms versus charged service totals of 20,839/20,539 ms; 886 encode/decode calls were observed above their declared budgets. This is a fixed-budget service-tape counterfactual compared with host wall observations, not physical timing. Sustained hardware 30 fps is not established. The pinned code and passing regression log show late ACK rejection after timeout and while parser ownership drains, with the sender anchor left uninstalled.
- **Memoization:** 156 paired source-frame IDs span 5 cases, 120 real-source rows, and 36 synthetic rows, with 98 distinct input content hashes. All 156 memo packet hashes match baseline bit for bit. The memo reduced recorded forward calls from 468 to 348 with 40 cache hits; this is computation reuse with unchanged packet bytes. Eight synthetic-noise rows exceed the cap. Prepare-time totals were about 4,219 ms baseline and 3,081 ms memo on the host; they do not establish physical performance. Cache scope is exact last-source/map/ACK-key/mode equality.
- **Input integrity:** the audit rehashed 38 declared local source pins and 2 source-media manifests before and after analysis; all matched. Synthetic scene hashes are counted separately from source-media files.

No result establishes installed custom hardware, live display timing, or a production 30 fps path. Missing fields remain unclaimed in the audit output.
