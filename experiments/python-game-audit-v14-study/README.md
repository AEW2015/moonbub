# Python Game v14 evidence audit

A stdlib-only evidence audit for the recent-reference, skip/residual, finite reference-ownership, and overlap-reference studies. The target is 720x480 coded with 720x405 active image at 30 fps. Absent or invalid result files remain pending/invalid and do not become success claims.

## Finalized codec evidence

The skip/residual result contains 7 cases, 154 source-frame identities, 117 unique RGB content hashes, and 770 decisions across GM, SR dense, SR exact, SR prune-2, and SR prune-4. Cohorts comprise 120 native-temporal rows, 16 held-out keys, and 18 synthetic rows. Each profile has 151 admitted packets and 3 cap rejections, with measured prepare work retained for all rejected candidates. All admitted full packets fit the 49,152-byte cap. The actual inverse checks stay within 2 or 4 YUV levels against quantized GM, and all profile runs report zero protected RGB565 mismatches. In the two native windows, exact syntax changes packet bytes by −3.31% and +0.52%; prune-4 changes them by −12.76% and −12.86%. Pruning costs added encoder work. This is a lossy bound relative to quantized GM output, not source-lossless or an application quality policy.

The recent-reference result contains 300 native source IDs plus 12 synthetic IDs. Its three native scenes repeat each input across profiles; 272 distinct native RGB hashes are represented. The AR01/AF01 runs record 924 attempted and 916 decoded packets; all 8 rejected candidates have measured preparation cost and exceed the full-packet 49,152-byte cap. In AR recent-8, 36 promotions publish and 41 promotion attempts record paid reconstruction/tag work totaling 247.36 ms. All 36 published bank/frame/tag bindings match the ACKed snapshot, and all 594 sampled prior-reference ID/tag bindings match the prior acknowledged state. Each accepted AR packet decodes to its recorded expected RGB hash. Two retained logical banks reach 2,073,600 bytes of int16 arrays; this is not peak memory or physical target memory evidence. The lost-ACK key fallback, physical-reader lease, publication boundary, and feedback binding behaviors are separately covered by passing regression tests; the benchmark rows themselves do not simulate an ACK loss.

Against the AR immutable profile, AR recent-8 mean packet size changes by −25.1%, −27.8%, and −28.7% on the combat, second native, and held-out windows. Active PSNR changes slightly in both directions. These are short precompressed 25/29.88 fps inputs, not live 30 fps captures. The audit does not compare these rates against v13's separate UI-cache study or turn serial host times into FPS claims.

The finite reference-ownership result records 13 cases, 1,152 capture events, 1,028 prepared packets, and 1,027 decoder commits. Its 15 code pins and external media hashes match. The audit rederives strict presentation counts from the capture window, checks each recorded work stage's host wall against its charged duration, verifies 3 sender slots, 2 ingress slots, 3 framebuffer roles, and 4 feedback descriptors, and checks that all cases drain at the end. In the two NACK cases, valid route NACKs arrive before host ACK expiry. The promotion-ACK-loss case records one lost feedback and expires by timeout without a fabricated NACK. The conflicting-feedback case receives both statuses for one promotion and expires it; separate passing regressions cover timeout during paid ACK work and decode completion during a deadline, where future state publication must be discarded or aborted after the work is paid.

These are finite Python runs driven by declared link, feedback, QSPI, propagation, capture, and vblank assumptions. Diagnostic presented IDs/s are model schedule results, not physical throughput. The run uses AR01/GF02/AF01 base packets only and does not integrate SR01 residual coding or HG01 UI overlays.

The overlap-reference result compares serial and bank-specific overlap policies in 9 cases over 828 capture events; its 17 code pins, external media hashes, and 9 regression tests pass. The 180-frame held-out pair, serial immutable-initial versus overlap recent-16-initial, has identical sets of 179 prepared and presented IDs; both omit only startup ID 1. In the five-second `[500, 5500)` schedule window, both present 150 IDs, covering 150 distinct native input hashes and 150 distinct decoded RGB hashes. The recomputed mean complete AR body falls from 18,688.592 to 12,216.603 bytes (34.63%); forward IPv4/UDP bytes fall from 3,542,023 to 2,317,634 (34.57%). Their diagnostic schedule counts are 30 IDs/s, and the measured active RGB565 MSE differs (14.98313 versus 14.85872) because references and reconstructed pixels differ. These results are conditional on the modeled links and measured host stages; they do not establish physical 30 fps or long-duration behavior, and do not integrate HG01 or SR01. The matched-delivery artifact is independently rederived and `analyze.py --check` passes.

## Audit behavior

Per-frame rows are used to recheck complete packet bytes against caps, retain paid rejected work, count coded modes and promotion attempts, verify pruning error bounds, separate frame identity from content hashes, and distinguish sender ACK state from receiver publication tags. Host wall timings, logical memory counters, virtual/declared service, and hardware timing remain separate evidence classes. The result JSON keeps unfinalized inputs pending.

Run `python audit.py` and `python -m unittest -v test_audit.py` with the project interpreter. The audit reads retained results and logs; it does not rerun study benchmarks.
