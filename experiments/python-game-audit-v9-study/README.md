# Python Game Bub v9 evidence audit

This stdlib-only audit independently evaluates the finite GM01 pipeline, serialized feedback, and RGB565 HUD patch studies. It keeps capture count, strict presentation, eventual presentation, and timestamp-window diagnostic presentation as separate measures; includes rejected work in service accounting; checks feedback epoch/frame binding; recomputes forward plus feedback wire accounting from actual byte fields; and reports slot/credit drain evidence separately.

The HUD audit treats each operating mode independently. A whole-frame cap does not establish an ROI pixel claim: claims need parsed ROI pixel dimensions and RGB565 color metadata. Predictor-unchanged claims are reported only when an explicit state check is recorded. Absent fields are listed as evidence gaps.

## Stored evidence audit (2026-11-03)

All 12 finite pipeline cases were read: eight baseline cases, two fault cases, and two noise stress cases. Strict presentation IDs are rederived from timestamps before capture end; eventual IDs include all stored presentations; diagnostic presentation IDs are separately rederived inside the stored `[500,1500)` ms steady window. Capture count is reported independently and is not called a diagnostic presentation count. The first baseline row has 57 strict presentations, 58 eventual presentations, 60 captures, and 29 distinct presentations in the 1-second diagnostic window (29 fps recomputed from those timestamps). All 12 end with sender slots, ingress frames, credits, and wait state drained. Configured initial key chunk loss, ACK loss, duplicate chunk and duplicate feedback faults each have matching observed timeout/duplicate events. Rejected candidate encode timing appears in the service totals: 8 rejects across the noise rows, 307.76 ms summed from the recorded row means and counts. These finite offline simulations do not establish physical display rate.

Serialized feedback results contain eight records. Recomputed forward traffic totals 40,843 bytes including duplicate datagrams; reverse feedback traffic totals 416 bytes. The actual stored datagram dimensions are 31-byte forward chunk header + 28-byte IPv4/UDP overhead (59 bytes per chunk before payload) and 24-byte feedback + 28-byte reverse overhead (52 bytes). All eight decoded payload counts return to zero and all three fault rows report drained. The ownership regression records GF01 losing the delivered pin after conflict and GF02 retaining it while allowing the original complete frame to commit.

The main HUD results contain 36 wrapped profile records. All 36 have zero mismatched original RGB565 words in their declared ROI, while all 36 exceed the 48 KiB whole-frame cap. This exactness is RGB565 word equality; it does not mean zero RGB888 MSE. The two separate flat palette cases also have zero RGB565 word mismatches and fit the cap, but are explicitly best-case synthetic examples. The display-only predictor test compares all YUV anchor arrays between patched and unpatched receivers, while decoded GM01 base hashes remain tied to the same base packet.

All 25 declared source pins and both external media hashes match before and after the audit. The audit records this status in `audit.json`. It does not rerun codec, timing, or video workloads, and it does not infer physical read-drain from an ACK.

Run `python3 audit.py` to audit any available `results.json` files in the companion study directories. Run `python3 -m unittest -v test_audit.py` for the lightweight helper tests. The audit writes `audit.json` beside the script and lists any expected inputs not yet present.
