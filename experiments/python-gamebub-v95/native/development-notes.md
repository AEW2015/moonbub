# V95 exact canonical palettes

`codec.hpp` supplies bounded U8 8×8 PIXEL records and full-plane parsing. This is a research wire format. CS95 outer CRC and the semantic root protect records; records have no individual CRC. Plane and frame boundaries reset the single previous-palette slot. No palette survives into a later frame or ACK.

The legal maximum record is **138 bytes**: a ten-byte own eight-entry palette header followed by 64 one-sample literal instructions, each requiring a token and one padded index byte. Own escape records need at most 106 bytes; RAW needs 66. Palette entries may be unused, including reused palettes that decode a subset. Own entries must be strictly ascending unique U8 values.

The encoder computes actual packed, prediction, escape (when enabled), reuse and RAW candidates. Prediction is deterministic dynamic programming over 65 positions, up to three operations and 64 run lengths. Equal-size candidates retain the earlier candidate; reuse is retained only when strictly smaller. Escape palettes use the most frequent cap values, ties by lowest sample value, then sort their entries. Thresholds include the four-byte position/length directory. A rejected tile never changes palette history. Palettes visit only the original mode-2 tiles, in canonical position order.

Profiles are control, P2 (cap2, cost16), P4 (cap4, cost24), P8 (cap8, cost40), E8 (cap8, cost40, escapes), W8 (cap8, cost64, escapes). Each profile actually filters the original coefficient blocks, prepares frozen AB and BR streams for the resulting whole plane, and picks the shorter coder for each context. RAW fallback is retained when the frozen preparation cannot supply real coded streams. Empty residual planes have zero entropy bytes. The control's empty palette directory costs 12 bytes, matching the legacy one-chunk directory.

The finite collector snapshots and hashes its sources, compiles with strict C++17 warnings in `gamebub-cu66-v69-build`, retains failed attempts, and records native `getrusage` peak RSS. Every retained record is independently decoded in Python and compared to its actual V82 canonical target tile. Every residual EC92 stream is independently decoded and compared to the original coefficient complement, independently recovered from the frozen BR88 source. Native parsing separately validates every variant. Archives are cohort-specific gzip shards bounded to 24 MiB raw, with compressed and raw hashes.

Generation timing includes the frozen AB source decode, all six profile searches and all six actual filtered AB/BR preparations and EC92 assemblies. Native and Python independent validation are separate. The native generator receives **predecoded V82 target pixels**; target generation, capture and DCT are excluded. These measurements do not establish a complete host encoder at 30 fps, device decode timing, physical timing closure or board publication timing.

An early attempt was deliberately expired through its watchdog after finding that the legal maximum-size fixture had been emitted into the malformed JSON array. The fixture placement was corrected and a fresh immutable campaign started. The failed snapshot remains retained for audit.

The first complete campaign passed 457 frames / 1,371 planes / 8,226 actual variants. Its six total plane payload byte counts were 4,279,629 / 5,689,636 / 6,331,801 / 16,580,727 / 16,694,953 / 33,893,479. Comparing the same profile across all three planes, control is smallest for every one of the 457 frames. These thresholds therefore do not demonstrate a full-frame gameplay/UI byte win. The measured all-six generation median was 62.72 ms (p95 137.54 ms), excluding the supplied target generation as described above. Any policy/report must retain this negative evidence and avoid a real-gameplay palette-win or full-host-30fps claim.
