Native controls accept `run(frames, codec, parameter, fps=Fraction(30, 1), output_dir=None)` and return `(decoded_rgb_list, info)`. Each source must be a 720×480 RGB uint8 ndarray. Outputs are indexed by source frame PTS. Codec aliases are `hevc`/`libx265`, `av1`/`libsvtav1`, and `jpeg`/`mjpeg`. Parameters are HEVC CRF 0–51, AV1 CRF 0–63, and JPEG qscale 1–31; these parameters are not comparable quality units.

All three controls use the same frozen GM01 `game_codec.ft.rgb_to_planes` and `planes_to_rgb` functions. The implementation path and SHA-256 are recorded. The full-range integer transform uses Y=(77R+150G+29B+128)>>8, Cb=((-43R−85G+128B+128)>>8)+128, Cr=((128R−107G−21B+128)>>8)+128, clipping before rounded 2×2 chroma reduction. The canonical inverse uses its existing interpolated chroma upsampling and integer coefficients. Native frames are filled directly with those samples, with no RGB conversion through swscale. HEVC/AV1 use `yuv420p` plus full-range signaling; JPEG uses `yuvj420p` and the same samples. Native decoded YUV420 planes go through the canonical inverse for every codec. Thus JPEG has no separately selected RGB/YUV matrix.

HEVC requests ultrafast/zerolatency, pools=none, frame-threads=1, WPP off, B frames off, lookahead zero, fixed 30-frame key period, scenecut off and repeated headers. AV1 requests preset 8, low-delay prediction structure, lookahead zero, temporal filtering off, scene detection off, lp=1 and PSNR tune. Both contexts request one thread, GOP 30 and zero B frames. JPEG requests native MJPEG baseline images, qscale mode, global quality qscale×118, qmin=qmax=qscale and one thread. Any unconsumed AVCodecContext option fails the run. A consumed option demonstrates API acceptance; emitted syntax and observed output availability provide separate evidence about resulting behavior.

The API records input RGB-to-plane conversion, frame-plane copying, encoder calls, packet decode calls, canonical inverse conversion, encoder/decoder opening and flush costs separately. Packet records retain PTS/DTS, key flags, size, SHA-256, submission index and input-frame lag. Decodes happen immediately after each encode call, including any packets returned at flush; output records show the earliest input index after which that output became available. A frame reported during flush is labeled accordingly. PTS association, uniqueness and complete output are checked. Zero future-input lag is a property to check in a measured run, not an assumption made by the API. CPU timings exclude stream inspection and artifact I/O.

`first_packet_elapsed_ms` and `first_decoded_output_elapsed_ms` share a sequence-processing fence that starts immediately before input0 RGB conversion, after both codec contexts open. Each packet is decoded during the same processing pass that encoded it; the first decoded-output fence ends when the canonical RGB output is ready. `sequence_processing_ms` ends after decoder flush conversion. This interval includes Python bookkeeping and unpaced processing of preloaded inputs. Per-output `decode_call_start_to_rgb_ready_ms` instead starts at that packet's native decode call and includes its canonical inverse conversion, excluding the encoder and previous packets. `timing_fences` records these definitions in JSON. None is capture-to-display latency; separate offline timing sums are not reported as end-to-end latency.

`output_dir` retains `stream.hevc`, `stream.obu` or `stream.mjpeg`, `extradata.bin`, `syntax.log`, and `ffmpeg-version.txt`. Real benchmark calls should always provide a distinct output directory. Without one, elementary bytes/extradata are returned as base64 and the syntax log as text. Coded-byte accounting is the sum of emitted packet payloads plus encoder extradata, including repeated sequence headers already present in packets; mux, network, transport, FEC and feedback overhead are excluded. The retained stream is exactly the concatenation of emitted packets. Library versions and requested context settings accompany the evidence.

HEVC and AV1 emitted streams are inspected using the separately versioned static FFmpeg `trace_headers` bitstream filter. `observed_syntax` records distinct emitted values and occurrence counts for selected fields; the complete raw trace remains authoritative. FFmpeg may print sequence headers once as extradata and again as an in-stream header, so occurrence counts are not necessarily frame counts. JPEG inspection parses emitted SOF0, DQT and DRI markers, including dimensions, precision and sampling factors. No filter/reference conclusion is inferred from an absent field. Sequence availability flags do not prove per-block filter execution; AV1 reference-slot indices and HEVC signaled buffering limits do not establish target memory consumption or actual maximum live frame storage. Requested one-thread settings/lp=1 bound encoder configuration but do not establish a one-OS-thread process.

The initial three-frame smoke observed HEVC I/P slices, zero signaled picture reordering, SPS buffering-minus-one 2, and SAO disabled; AV1 key/inter displayed frames, no show-existing frames, and CDEF/restoration availability enabled. JPEG emitted eight-bit SOF0 with 2×2 luma / 1×1 chroma sampling. Every tested codec emitted and decoded each frame during its matching input call, with no packets or frames returned only at flush. These observations describe this smoke only; benchmark runs retain their own evidence.
