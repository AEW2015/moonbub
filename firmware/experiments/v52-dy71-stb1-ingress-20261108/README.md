# V52 STB1 ingress source candidate

Source-only candidate based on exact V48. No target build, release image, installation or physical qualification has occurred. The installed handheld/FPGA are untouched. V49/V50/V51 native optimizations are absent.

The sole data-path change is compressed ingress: explicit ABI3/caps `0x3f`, STB1 magic/version, fixed 256-word credit reservation and one bounded descriptor/payload burst instead of per-word scalar credit/write/count operations. The new `Profile::Dy71Stb1` is distinct; legacy `Dy71Bulk` retains caps31 and its meaning. V027 ABI2 is refused before writes, as is a caps31 image advertising ABI3. The actual legacy V48 network driver is also tested to refuse the new profile before writes.

The driver caches the existing HU span and advances the existing source CRC before temporarily reversing each four-byte word in the existing 1024-byte input buffer for BE SPI serialization. A `repr(align(4))` wrapper replaces that array with exactly the same1024-byte storage; it does not add a second packet buffer. Both driver and raw Adapter reject unaligned slices before mutation. It pads only the final word and saves at most three overwritten padding bytes. Source and padding are restored on every returned success/error. The raw Adapter SPI method borrows this transformed slice directly: no additional `[u32;256]`, application bounce buffer, new driver allocation or scalar payload fallback. Metadata uses20 bytes; CSR reads use at most24 bytes. The SDK SPI/DMA implementation may still copy or allocate internally; that behavior has not been physically measured, so the core-only no-allocation proof does not cover the complete SDK.

Stored-prefix acknowledgements require actual native drained prefix and CRC, exact generation/ticket, full credits, no armed/blocked/fault state and zero native staging faults. A busy first beat invalidates all later fields of that live sequential read. Additional ready/status, generation and ticket reads surround the check. A FIFO being empty while its descriptor remains armed is not completion. Tickets remain monotonic across frames; no wrap/reset or silent attachment to an existing owner is permitted. The existing final native written/length/CRC/fault check, real SEAL/START, HUD/HBU1 writes/readback, native commit and physical presentation observations remain in place.

The concrete Adapter keeps the existing `Device::try_lock`, captured FPGA program epoch, MaintenanceGuard side-effect marking, 16 MHz SPI limit, counters and single-transaction semantics. Contention is retried only when no transaction began. Uncertain/short I/O, epoch/ownership loss, corrupt snapshots and expired absolute deadlines fail closed, poison the STB1 driver and enter the existing retained/quarantine path; no reprogram/reset/retry is fabricated.
