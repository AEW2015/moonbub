# V54 failure-only STB1 diagnostics

Source candidate based on exact frozen V52. No target build, firmware image or hardware change has been performed for V54. V52 and the FPGA/P&R inputs remain unchanged. V49/V50/V51/V53 optimizations are absent.

Only the failure observation path changes: the receiver captures thirteen STB1 CSRs at0x700..0x730 once each after a run error, before the existing passive FPGA observations. The same retained MaintenanceGuard and epoch-checking Adapter are used. There is no write, retry, lease release, reset, native/wire/Error-enum change or normal-path SPI/log output. A lazy context closure is not called on success. The tiny `Input::diagnostic_identity` accessor only returns the cached Copy identity; it performs no socket I/O, acknowledgement or state change.

The record binds source Progress active/ordinal/frame/generation/phase/progress timestamp/stored prefix, plus available current DYN1 session/capture timestamp/frame/reference. Progress and current identity can describe different frames, particularly near header errors; both are retained independently, not forced to agree. `identity_valid=0` explicitly means no current cached DYN1 identity. Progress timestamps and snapshot start/end are local monotonic microseconds. `capture_us` belongs to the sender's timestamp domain and is for identity correlation only; do not subtract it from local monotonic times or assume synchronized clocks.

The CSR sample has attempted/valid masks, result flags, first read-error index/code and raw values. There are thirteen attempts maximum, with no retry or yield. A20ms budget is checked **before** each call; it is not a hard deadline and one underlying SDK SPI operation can exceed it. Epoch and contention errors remain explicit. Invalid/unattempted words are zero with their validity bit clear. STB prefix/CRC registers themselves are masked while the RTL fence is false, so even a valid sampled zero is not proof of an empty packet.

The immutable local snapshot emits four `STBF1` payload records: H metadata/identity, C progress/session context, A seven CSR values and B six CSR values. A CRC32 binds all metadata, context and values in explicit little-endian field order. Maximum integer-value payload lengths are119/186/104/95 bytes, all≤192. Delivery is best-effort, the live CSR reads are NONATOMIC and sampling occurs after the run returned an error. These are not failure-onset timestamps, first-fault history or proof of RF delivery. Missing/truncated lines cannot be treated as a complete observation. There is no new paced/re-export storage; existing immutable DY45 snapshots and checksums remain unchanged.
