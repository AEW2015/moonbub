# DY71 board-math binding and blocked physical-shell proposal

This isolated successor binds the qualified PIPE owner/grouped memory profile to the root's exact math-v004 datapath: SHA lookahead `f29332de…`, indexed IDCT `fe1d7f36…`, reset-light dequant `e2abdd9e…` and reconstruction `3ea16f4e…`. Canonical strip RAM, entropy v4 and all address/map/controller/arbitration policy sources are retained. Only the new top/receiver module bindings are derived here; normalization checks prove the direct transaction owner, COMMIT/leases and native HUD connections unchanged.

`qualification-native-v001.json` records complete actual pin-model KEY/P/P and bounded control success. Both control and frame logs are byte-identical to the qualified PIPE/grouped parent. The frame log SHA-256 is `0d19b4884c376d251cff492fe1535126b55dcede1268ef6b1f8092578f4d3c33`; cycles remain 2,049,238 / 3,438,483 / 4,552,368, with zero underruns/black lines and identical stage, presentation, first-canvas and complete-raster identity events. This is cycle-preserving timing repair, not a new 30-fps result.

`physical-shell-proposal/` is concrete but deliberately **not buildable**. Its source generator parses all 140 actual system ports and 84 DY71 CSR ports, checks common widths/directions and rejects unmapped inputs. No `USE_STRIP`, painter or RGB alias is supplied. It retains the reference's clock/pin budgets, reset/quarantine and QSPI bridges, while changing both USERID and USR_ACCESS to `0x44593731`. The CSR magic is also DY71, ABI `0x00010000`, local capabilities `0x0f`.

The current inherited LCD endpoint uses `request_sync*[0]` functionally inside `requests_idle`. That is a known CDC blocker. The proposed timing Tcl begins with an unconditional error, and the dependency manifest has `BUILD_ALLOWED=false`; root must select and verify the separate SYNCsafe endpoint before a board build. The first-stage fanout guard draft additionally requires each LCD first-stage Q to feed only its corresponding second-stage D. It has not been bound or executed against a synthesized netlist.

The direct-only held `completed_bad0/1` payloads also need explicit routed bounds to `loaded0/1`. The timing proposal uses the existing 10 ns bundled-data budget and exact two-source/two-capture object guards; it does not hide those functional payloads with a false path. Object names, hold behavior and CDC protocol still require review against the selected SYNCsafe netlist.

No Vivado job, BIT generation or hardware operation was started here. Complete DY71 local-CSR/physical-bus tests, correct endpoint binding, fit, routed setup/hold, CDC, external QSPI hold and controlled hardware tests remain root selection gates. The old `prepare_board.py` cannot be reused unchanged because it hardcodes obsolete system ports and `0x43553731` identity.
