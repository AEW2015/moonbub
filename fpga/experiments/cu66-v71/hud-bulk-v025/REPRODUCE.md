# V025 development source and dependencies

The physical baseline remains V42/V023; this source directory is a development candidate. Consult the root `docs/cu66-v71/V43-BULK-HUD-DEVELOPMENT-20261107.md` for gate status and the failed attempts. Do not infer hardware readiness from these scripts or the presence of a synthesized checkpoint.

`board-source-v003/inputs` is the exact 76-file RTL/header/constraints snapshot for the current candidate. `source-freeze.json` hashes every input; `selection.json` names the actual top/part/core/profile. It needs no separate GameBub repository for RTL rebuilding. The supplied scripts use Windows Vivado 2025.2 with `xc7a100tcsg324-1` support and unique short `C:/vtmp` paths. Copy the bundle to a new output directory, then run its `run-phase.py synth` and, after checking the execution record, `run-phase.py implementation`. These scripts emit checkpoints/reports only. They do not program hardware or create a BIT.

The executed component harnesses retain historical `C:/mb70` paths and unique run labels. Reproduction requires Icarus from `C:/msys64/ucrt64/bin`, Vivado's matching UNISIM library/XSim tools, and the original native-word files in `native-gold`. Their native CRCs are `358486a6` and `9b082f5c`. Pin/legacy tests additionally read the exact V023 frozen baseline at `C:/mb70/dy71-v023-20261106-v001`; `baseline-source-v023` supplies those inputs and manifests if that directory is absent. Do not overwrite an existing workspace's baseline; verify its hashes first. Use fresh run labels/output directories when repeating tests, retaining the original logs.

The inherited full-decoder/oracle checks used by `image-gates.py` reference the original local V023 evidence and helper scripts. Those machine-local proof paths are not a portable, independently completed whole-system gate supplied by this component bundle. The manifest and reports distinguish inherited unchanged-source evidence, new component tests and pending physical checks. `c_check_handoff` is unavailable in this environment; manual hash integrity is not equivalent to that service or a functional proof.

The ESP32 source snapshot is `firmware/experiments/v43-dy71-bulk-hud-20261107`. Its locked Rust/ESP-IDF/Slint dependencies require the recorded ESP toolchains and cached/fetched packages; the existing build helper uses the local ESP target cache. Final ELF/BIN/UF2 are retained locally under `release-bulk-hud-v002`, with published hashes. There is no new Windows uploader, network contract, live encoder or codec format in this change. Keep the original `cbbd85fda` DYN1 uploader and KEY/P fixtures.
