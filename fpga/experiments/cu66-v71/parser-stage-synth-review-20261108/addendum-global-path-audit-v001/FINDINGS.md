# Unplaced command-to-entropy path audit

The inspected path is **synthesized/unplaced**, not the current routed critical path. It launches `control_plane/command_state_reg[2]_rep` and ends at `receiver/base/entropy/state_reg[0]/D`: −1.791 ns estimated slack, 11.643 ns data delay, 18 levels, 3.638 ns logic and 8.005 ns estimated routing (68.754%). Three CARRY4 plus fifteen LUTs appear. Original report and exact source hashes are bound; no new Vivado process or code/constraint change was made.

## Semantics a future repair must preserve

- **Command ownership and abort:** control captures an immutable command-field snapshot only when idle with a fresh submitted sequence. `ABORT_FRAME` succeeds only while busy and stage<9; the receiver additionally allows abort outside IDLE/COMMIT_ACK/DRAIN. Kill masks new requests/configuration immediately and holds accepted work in drain. Do not add an unqualified one-cycle window for new acceptance or stale operands.
- **Begin/start/release:** BEGIN requires available/fenced staging, nonzero fresh generation, bounded packet length and no quarantine. START requires sealed matching generation and no active frame. Release waits for frame completion, quiet memory, quiet packet bridge and no staged response. The arbiter's `busy` deliberately includes a same-edge new upstream acceptance, preventing premature staging release. BEGIN logic is a related control contract; no named BEGIN signal is proven to be the measured path's limiting expression.
- **Address and parser priority:** parser requests win over base requests. The base byte address adds the selected validated plane start in17bits; invalid/overflowing/out-of-packet addresses must not be truncated into an accepted request. The bounds-fault code0x75 and parser/base pending ownership remain intact. Do not bypass the comparator simply to shorten ready.
- **One accepted identity:** the arbiter captures address/generation/sequence/owner exactly once, queues before backend issue, then awaits the matching response. Round-robin `next_owner` fairness must remain correct under simultaneous CPU/decoder requests. Bad outstanding identities are forwarded to their retained owner and fault; unsolicited/preissue responses fault without routing.
- **Decoder handshake and cancellation:** a stalled registered request keeps its address/valid until actual acceptance. Memory-read count advances only on valid&&ready. Abort clears new valid and drains an already accepted read; it explicitly handles abort coincident with valid&&ready. A future skid/register stage must retain its own pending identity, prevent duplicates and drain/release correctly rather than fabricating a response or losing an accepted byte.
- **Reset/fault separation:** existing joint resets flush the transport/owner together. Transport/packet-identity/burst faults quarantine admission; they are not directly ORed into the selected `abort_i` wire in this source. Do not change that relationship, weaken generation/tag/CRC checks, relax the clock or hide paths with false/multicycle exceptions as part of a timing-only repair.

## What this audit does not select

No pipeline, grant factoring, fanout replication or placement constraint is selected here. First compare the final routed paths and real routing share with this estimate. If this chain remains critical, a narrowly specified request/grant boundary or algebraic acceptance factoring can be reviewed separately, with actual primitive/fanin truth data. Required tests include simultaneous p0/p1 requests, ready stalls, parser/base priority, overflow bounds, abort on each side of acceptance, late/bad/unsolicited responses, release on the acceptance edge, reset with queued/outstanding work and a fresh generation after drain. Any added stage also needs an explicit latency/watchdog contract. None of those future proposals is authorized by this audit.

`source-bindings.json`, `first-path-excerpt.rpt` and `path-cells.tsv` retain reproducible anchors. `path-cells.tsv` is a convenience extraction; wrapped CARRY4 lines are authoritative in the full excerpt. The running P&R remains root-owned and unchanged; V028 remains selected until every final gate and explicit selection passes.
