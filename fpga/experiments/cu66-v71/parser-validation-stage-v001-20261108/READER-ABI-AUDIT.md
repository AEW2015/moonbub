# Read-only firmware dependency audit

The staged parser changes the timing and possible stale content of provisional diagnostic values after cancellation; it does not promise cycle-exact diagnostic identity. Actual receiver selectors are 0x0a8(block size),0x0ac(plane block width/block size),0x220..22c(parser reference tag),0x230..23c(parser HUD reference tag). These are unqualified diagnostic wires. Metadata capture into the functional receiver is instead p_meta_valid&&p_meta_ready, with !fatal_non_hud; base startup follows its own state fence.

The inspected exact published V54/V55 custom-codec local/network drivers do not read those provisional selector ranges. HUD preparation consumes qualified control-plane0x300..32c snapshot fields, with flags/ticket/generation/frame/reference fences. Software requests likewise use0x330..344 qualified ticket snapshots. Indirect diagnostic selection via0x200/0x204 after completed presentation checks accepted reference tag0x98..a4 and frame IDs0x1c/20; these are not the provisional parser tag selectors. Passive failure sampler reads350/354/358/35c/360/110; STBF1 sampler reads700..730. No guarantee depending on invalid parser payload was found in these actual custom-codec readers.

Global timing.rs has a direct0x0a8 read under separate TIM1/schema identification and a different register/profile context; that numeric match is not a custom-codec parser-selector consumer. The adapter remains capable of arbitrary bounded reads, so this audit is about actual call sites, not claiming no external tool can observe the provisional change. A diagnostic client inspecting invalid/stale fields must not treat them as a validated frame, and existing debug codes0..18 remain preserved with new code19 appended.

Receiver watchdog age still increments in METADATA. The added validation cycle can change the outcome at an exact deadline boundary: an older parser may finish/report its error before the watchdog, while the candidate may reach timeout first. If p_error and watchdog are simultaneously true, the existing fatal ordering still prioritizes parser error. No timeout was widened. Parser-only tests have no owner watchdog and cannot qualify boundary behavior; actual receiver/full-system boundary tests remain required before claiming that scope. Software watchdog30s/SDK40s parameters are untouched.

This dependency audit supports a narrow compatibility statement for the inspected V54/V55 reader logic. It is not a full ABI/hardware qualification or a promise that every observer sees identical invalid payload/cycle timing.
