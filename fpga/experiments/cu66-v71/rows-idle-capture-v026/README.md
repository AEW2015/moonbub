# V026 idle tile-payload capture timing candidate

This is a timing repair candidate on top of V025's bounded bulk HUD interface. The V43 ESP32 image and ABI2/cap1f/HBU1 contract are unchanged. Intended V026 BIT USERID/USR_ACCESS is `4459373e`. No hardware has been programmed with this candidate.

The reported V025 pre-route path ran from a command-state register through nine LUT levels of kill/abort/ready logic into a 512-sink tile-payload capture enable. V026 captures tile pixels while the row writer is idle, and holds them during `write_busy`. A valid tile handshake still captures the accepted payload on the same edge that starts the writer. All token, validation, handshake, counter, RAM write-authority and control resets remain. Only the 512-bit payload reset is removed. Physical LCD timing/scanout, SDRAM controller/pins/budgets and clocks are unchanged; this module serializes canonical hash rows.

Executed gates:

- `pair01`: one- and two-strip-bank variants, two complete KEY/non-key frames each; over two million qualified output bytes total, matched cycle-by-cycle controls/counters/last flags, authoritative payload and RAM write authority, with stalls, abort, reset and invalid metadata cases.
- `proof02`: induction over actual old/new RTL control projection and `write_busy -> 512-bit payload equality`, for both bank counts. The cache-valid/bank-full invariant is asserted and proved, not assumed. The always-capture mutant fails, and the non-vacuity counterexample reaches payload ownership. The unobserved strip RAM/read-output data is optimized away: this is not a claim of formal whole-memory or whole-codec equivalence.
- `proof01` is retained as an inconclusive depth-limited induction attempt. It is not counted as a passing proof.

Full fast/slow native raster integration passed with the exact selected new row source in the real decoder graph. Each case accepted/presented both original frames, rejected none, verified all 42,240 HUD words and matched the native canonical/display raster. The checked SDRAM models use `(T_AC, clock flight, T_OH)` in ns of `(2.223, 0.757, 2.223)` and `(8.489, 3.768, 2.223)`. They use the existing scalar ABI1 CSR simulation platform; new bulk/ABI2/pin behavior has separate tests. Native HU CPU runs outside HDL, so reported virtual elapsed time is not hardware playback FPS. Legacy SDK log labels are preserved; source-binding records identify the actual compiled graph. FPGA synthesis/routing are pending. No timing, BIT, physical-playback or 30 fps acceptance claim follows from these results.
