# V91f bounded packed-write overlap

V91f copies the V91e packet-to-packed-scratch-to-dense pipeline and adds a runtime `write_overlap` control, captured on integrated start and passed as `begin_overlap` at scratch allocation. The selected tile-clearing path remains validity-mask clearing (`serial_clear=0`). With overlap disabled, the V91e controller paths and state IDs remain unchanged. The measured campaign runs overlap off/on against the unchanged FAST/SLOW memory profiles; it compares the disabled path with frozen V91e mask-clear receipts at matched seeds.

The packet ingress remains the V91d module, with the unchanged V91 Rice and V91b context parsers. Packed format, packet admission, four reader caches, AC heads, tile merge and dense reader scheduling remain unchanged. This experiment ends at accepted dense coefficients. It has no pixel, IDCT, frame-publication, display, physical-memory, synthesis-fit or clock result.

The overlap writer has two bounded 16-byte payload buffers: an immutable write slot and the assembler for the following line. The existing scalar pending-record register holds at most one 2- or 4-byte record separately; it is not a third line buffer. The slot owns a line from enqueue through offer, physical acceptance and matching ACK. Its address, payload and epoch stay immutable under request stalls and accepted-request latency. The assembler can continue receiving records during that latency. When it fills while the slot remains occupied, `FLUSH_LINE` (state26) holds its bytes and backpressures the coefficient producer until the slot retires. A successful matching ACK may retire the slot and enqueue the held line on the same edge. The new line can be physically accepted on a later edge. The external interface permits at most one accepted request, including reads and headers.

The writer advances its packing address on slot enqueue. Header writes use the original sequential request/ACK states. `seal_ready` requires the producer to have finished every context and the assembler, slot and accepted request to be empty. Both header writes must then receive physical ACKs before `sealed` asserts and descriptor reads start. Thus packet completion can wait at the seal barrier while a final data write is still pending; no early local write acknowledgement advances the seal or reader.

Reset and a matching abort discard unaccepted local bytes and any unaccepted offered slot. An accepted write remains an external hazard, with its original payload and epoch retained until a matching ACK; bank allocation remains blocked in `DRAIN`. Held warm reset cannot erase that hazard. A stale-epoch abort leaves the active owner intact. A mismatched response cannot retire the real accepted request. Write-ACK errors and mismatched responses take priority over replacement enqueue and prevent publication. Producer validation failure also drains a previously accepted write, including a request accepted on the same edge as that failure, while discarding unaccepted storage.

State IDs0..25 retain their V91e meanings. State26 is `FLUSH_LINE`; IDs27..31 remain reserved. Packet and scratch occupancy histograms each reconcile independently to integrated running cycles. They describe concurrent stages and must not be summed together. The physical-pending count is sampled from the accepted-request owner, independently of scratch controller state.

All V91e telemetry fields and ordered `request_service_hash` remain. Case rows and tile events add `write_overlap`. `observability.highwaters` adds `write_slot` (at most1) and `owned_lines` (slot-valid plus nonempty-assembler occupancy, at most2). `observability.write_overlap_counters` reports data-slot `enqueues`, `physical_accepts`, `physical_acks`, `full_wait_edges`, and `packing_during_write_pending`. These slot counters exclude the two sequential header writes and remain zero when overlap is disabled. `packing_during_write_pending` counts INGEST/APPEND edges coincident with a physically accepted write awaiting ACK, including its ACK edge. `full_wait_edges` counts state26 occupancy and can include a partial context-tail line waiting for the slot. These observations establish actual concurrent packing and write service; overlapping counters are not disjoint removable delays.

The external RAM model remains one 262144-byte bank. FAST acknowledges after one edge. SLOW uses write16/read18 plus address/seed jitter0..3, with finite request, packet-input and dense-output stalls. Accepted writes commit only on their delayed physical ACK, including through cancellation. Each success compares the entire packed image and every dense coefficient against independent golden bytes and checks that every expected line was written and read. The service hash covers ordered direction/address/service latency and write payload words, excluding epoch and absolute cycle, so the overlap variants can compare the same ordered physical traffic.

`tb_pipeline.cpp` retains the eleven V91e directed checks and runs them in each overlap mode. Six additional overlap checks cover full-assembler backpressure with simultaneous ACK/enqueue, cancellation of an unaccepted offered write, accepted-write plus partial-assembler cancellation under held warm reset, ACK error with a full assembler, stale response with a full assembler, and packet completion blocked behind a delayed final data ACK. The integrated packet API always aborts its current owner and validates coefficients before scratch admission. `tb_scratch_hazards.cpp` therefore drives only public scratch ports to cover nine lower-level cases: unaccepted, accepted and same-edge-accepted producer semantic failures; stale abort with an accepted owner; stale response and ACK error with a full assembler; simultaneous ACK/enqueue; ACK during held reset; and stale abort with an unaccepted offer. It requires a terminal JSON `TEST_PASS` and has a bounded edge watchdog.

Run `scripts/cu66-v91f/run_pipeline.py` from the repository root. The runner snapshots the selected sources and vectors, uses fatal Verilator `-Wall`, enables RTL assertions, builds C++ with `-Wall -Wextra -Werror`, and limits compilation to `-j2` in the existing Docker environment. It retains strict compile logs, vector hashes, per-case metrics, joined tile traces, standalone scratch-hazard output and verdicts. The measured mask-clear corpus has four configurations per vector: overlap off/on × FAST/SLOW. The complete corpus retains historical cases and the expanded actual/synthetic/raw workloads; added vectors do not by themselves establish a performance improvement. Consult the campaign results and baseline comparison for measured outcomes.
