# Live canonical write/validation join

This experiment instantiates the unchanged V91k packet-admission, coefficient,
inverse-transform and canonical reconstruction pipeline concurrently with the
unchanged V91l C2/HUD/seal validation and atomic bank controller. The new
single-byte joiner accepts a real reconstruction byte, requests its candidate
bank write, waits for the matching tagged physical-service ACK, and only then
delivers that byte to the hash input. This is a behavioral external-memory
service experiment, not a mapped SDRAM or display implementation.

`cs88_live_v91l.sv` is regenerated by `make_wrapper.py` from the frozen producer
and validator port declarations. It intentionally exposes their diagnostics to
retain the previous coefficient/transform/reconstruction scoreboards.
`tb_live.cpp` is regenerated by `make_bench.py` from the frozen V91k bench;
its old arithmetic, tuple, ownership and finite scratch/reference assertions
remain active while the live publication scoreboard is added.

## Byte ownership

`cu66_write_hash_join_v91l.sv` has four states: IDLE, OFFER, WAIT_ACK and DELIVER.
There is one registered byte and at most one accepted external request. The
write identity comprises 32-bit epoch and token, two-bit bank, and 20-bit byte
address. Its token increments across warm resets; a cold reset requires
external quiescence. Error 0x81 reports a mismatched ACK without releasing the
real pending request. Error 0x82 reports a matching bus-error ACK, retires the
physical request and suppresses hash delivery. Warm reset or cancellation
discards unaccepted/local work but retains an accepted request until its
matching ACK drains. A new internal `start` is legal only while IDLE; the
wrapper blocks external starts until producer, validator and writer are ready.

Canonical candidate addresses are raster Y/Cb/Cr offsets, derived from the
producer's plane/tile/byte tuple. The hash stream retains native tile order.
HUD candidate offsets start at 518400 and are derived from a wrapper-owned
counter. The wrapper rejects an incorrect software index, incorrect last flag,
or any extra HUD byte before issuing an invalid write. A per-transaction active
gate prevents next-frame software bytes from entering while a previous
producer's completion remains high. Accepted starts take priority over the
previous validator completion when updating that active gate.

The validator's write-drain authority comes from this adapter's actual owned
request/delivery state. Its producer completion comes from the actual V91k
pipeline. Registered admission fid/key/generation are bound to the accepted
start metadata. Header commitment extraction and actual native HUD semantic
decoding remain C++ work before the measured RTL start; they are not claimed
as an all-RTL packet/HUD endpoint.

## Native history and timing

The campaign uses original native c0_f0 and c0_f1 commitments and HUD payloads
with the qualified BR88 encodings `actual_001` and `actual_006`. The new delta's
reference reads use the previously validated candidate bank's actual bytes.
Its inherited qcache input uses 1350 actual registered lookup results captured
from the accepted predecessor and promoted only after validated commit. Those
bytes are compared with independent prior-scale goldens, not substituted by
an oracle assignment.

Each nominal frame requires 518400 canonical plus 42240 decoded HUD writes and
1025 real RTL SHA jobs. FAST/SLOW service is finite and seeded. The runner
records start, first/last accepted outer byte and validated-commit fences,
plus candidate write/ACK counts. The last candidate ACK timestamp is not
exported; commit assertions require that physical write and delivery leases
have drained. Serial qcache preload and C++ HUD decoding remain outside the
start-to-commit fence. No achieved clock, physical memory schedule, RGB565/HUD
overlay, scanout, sustained source cadence or ESP32 execution is qualified.

The C++ negative tests wait for the RTL's latched `transaction_faulted` status
or a validator error. Post-edge combinational mismatch is deliberately not a
fault verdict: the RTL counter can advance before the next C++ source update.
All failures and superseded source snapshots are retained separately.
