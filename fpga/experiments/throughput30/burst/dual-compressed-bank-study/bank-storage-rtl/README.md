# Isolated dual compressed-bank storage prototype

This experiment extends the neighboring `../ownership-rtl/` control prototype with **two actual 49,152-byte synchronous byte arrays** and a decoder-side read interface. It is separate from production RTL and does not instantiate the production JPEG decoder, physical FPGA BRAM primitive, QSPI/CDC bridge, framebuffer, display or external memory. The local controller copy adds only a decoder-grant length output; `run.sh` reconstructs it from the prior controller and rejects any unexplained differences.

Each accepted ingress byte is written, on the common clock, to the controller-selected bank and offset. The controller still enforces declared length, CRC, abort and bank ownership as described in `../ownership-rtl/README.md`. A read can address only the bank belonging to the currently granted decoder frame, and only offsets less than that frame's declared length. A request presented before a rising edge produces registered `read_valid` and `read_data` after that edge; no asynchronous read response is provided. `read_ready` becomes active after the decoder grant has propagated into the storage wrapper. Requests without ownership, outside the declared length, or coincident with grant/release produce `read_error` with `read_valid` low. `read_data` may retain an old value when invalid; callers must use `read_valid`.

Reset clears ownership and read-valid state and gates a pending abstract RAM write, but intentionally does **not** erase either RAM array. Reusing a shorter bank cannot read the old trailing bytes through this interface because the new declared length limits access; this is not a security-erasure guarantee. The testbench also resets during decoder ownership and while an ingress write strobe is pending. The controller's abstract front is still only a frame ID; pixel-buffer atomicity and actual memory drain are not established here.

## Verification

The full bounded wrapper passed in the development container:

- Frames of 1,024 and 1,536 distinct patterned bytes were written to separate banks. The test read every byte of frame 0 while simultaneously writing frame 1, then read every byte of frame 1. The 1,024 simultaneous read/write cycles checked distinct-bank payload isolation.
- CRC failure and explicit abort never granted read ownership; a reused three-byte frame could not read a stale fourth byte from its previously longer bank. Tests cover no-owner reads, out-of-range reads and registered response behavior.
- A full **49,152-byte** frame was written and every byte read back; offset 49,152 and a declared length of 49,153 were rejected. Reference CRCs for the patterns and full-size frame were independently recalculated with Python `zlib`.
- The test checked **51,715 byte reads**, including the full-size frame, and the final abstract front ID. Two separate local mutants—bypassing the length check and reading the wrong bank—failed at their specific expected assertions; neither produced the pass marker. These are directed simulations, not exhaustive formal proof.

With optional Yosys 0.52, `read_verilog -sv; hierarchy -check; proc; opt; memory_collect; check; stat` completed with zero reported problems. Its generic JSON contained two `$mem_v2` cells named `compressed0` and `compressed1`, each **49,152 × 8**; `results/generic-memory-shape.json` records the checked shape. This is **not** technology mapping or proof that Vivado will infer the desired BRAM ports, capacity, timing or fit. The source contains a `ram_style="block"` intent attribute only. The baseline's constrained BRAM and timing headroom are documented in `../baseline-resource-audit/`.

All ingress, ownership, read and reset signals here share one simulated clock. There is no QSPI DMA or CDC ordering, backpressure/byte-write acknowledgement, stale generation token, real FIFO credit handling, simultaneous independent resets, physical memory collision characterization, decoder integration or timing closure. `decode_done`/`decode_fail` and `vblank` are synthetic test inputs. In particular this does not establish safe behavior for lost/ambiguous aborts, decoding/pending-frame aborts, abort/vblank races in production, real network input, physical SDRAM, or sustained 30 fps.

To reproduce, set `BUILD_DIR` to a new empty directory and run `./run.sh` with Verilator 5.x, C++ and Python. Set `YOSYS` to a Yosys executable to also run the optional generic-memory check; package-specific `PYTHONPATH` is the caller's responsibility. Each simulation has a 90-second wall timeout; compilation is outside it.
