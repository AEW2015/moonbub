# Isolated decoder-facing little-endian word reader

`word_reader.sv` is a single-clock synthesizable-style prototype layered over `../bank-storage-rtl/`. It requests one synchronous byte at a time from the **decoder-owned** compressed bank, packs bytes in increasing-address/little-endian order into 32-bit words, and presents `out_data`, `out_strb`, `out_valid` until `out_ready`. A partial final word uses low-lane strobes `0001`, `0011` or `0111`; bytes in unused lanes are zero. A complete word uses `1111`. `frame_done` pulses only after the final output handshake; there is no separate `out_last` signal, so a consumer needing it must use the granted length and completion contract.

The reader accepts `start` only while `owned` is true and the supplied granted length is 1–49,152 bytes. It latches the granted length, issues one outstanding byte request, and waits for `byte_valid` or `byte_error` before the next byte. A byte-port error cancels the frame. A duplicate start is rejected without replacing the current operation. With ownership held, output data/strobe/valid stay stable under backpressure. `out_valid` is gated by `owned`; revocation cancels even a held word and prevents a simultaneous ready/release handshake. The integrator must provide a **synchronous, correctly timed ownership signal** that deasserts when the bank is released. The testbench explicitly drives `owned = read_ready && !decode_done && !decode_fail`; this policy is not wired into the production design. There is no CDC or asynchronous-reset safety claim for that gate.

The existing byte storage's one-edge registered response is exercised directly. The test rejects start without ownership, start after release, and byte-port error; it also checks reset while an output is backpressured. The reader has no transaction-generation tag, so stale late memory responses, lost acknowledgments, unrelated-clock signals and arbitrary integration reordering remain design/verification work. It does not instantiate the JPEG decoder and makes no claim about its exact `last`/reset semantics or an end-to-end frame display.

## Checks

A full Verilator wrapper run passed **12 frames, 196,634 bytes, 49,164 output words**, including 1-, 2- and 3-byte lengths/tails and 49,149-, 49,150-, 49,151- and 49,152-byte frames. Every output byte, strobe and zero-filled unused lane is checked against an independently generated deterministic byte pattern. The final three near-cap lengths exercise 1-, 2- and 3-byte tail words; the cap itself is word-aligned. Reference CRCs for all frame patterns are independently checked with Python `zlib` before simulation.

The same test checks both bank owners: a second distinct-pattern frame is received into bank 1 while bank 0 is decoder-owned, then both are read out and compared. Output stability is checked on every backpressured cycle, including **49,163 sampled stalled cycles** in the recorded run. Directed controls cover no-owner/duplicate start, ownership release while stalled, release coincident with downstream ready, reset during a held word, and injected byte-port failure. The stall count is a test observation, not a throughput or FPS result.

Three local mutants are built separately: reversed byte-lane order and an incorrect three-byte strobe must fail exact word comparison; disabling ownership cancellation must fail the released-bank assertion. The wrapper requires each specific failure and rejects a pass marker. With optional Yosys 0.52, `read_verilog -sv; hierarchy -check; proc; opt; check; stat` reported zero problems for the reader alone. This is a generic elaboration/process check, not FPGA technology mapping, timing, physical BRAM inference, whole-design fit or formal proof.

Run `./run.sh` with Verilator 5.x, a C++ compiler, Python and a new empty `BUILD_DIR`. Set `YOSYS` to an available executable for the optional check; package-specific `PYTHONPATH` remains the caller's responsibility. Each normal/mutant simulation is bounded by 90 seconds wall time; compilation is outside that bound.
