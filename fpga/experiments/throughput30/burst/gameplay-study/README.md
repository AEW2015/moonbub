# Gameplay-derived QSPI behavioral test

A short test used a local, precompressed Mass Effect combat clip (SHA-256 in `manifest-10.json`); no clip or frame is redistributed here. The source is 512×288 and 25 fps, already compressed, so these are **not native-quality, independent 30 fps gameplay captures**. FFmpeg 7.0.2 sampled it at 30 Hz, upscaled it to 720×405 and padded black to 720×480. The existing restricted JPEG encoder used Pillow 10.4.0, quality 65 and 4:2:0. Two frames were repeats: 8 distinct JPEG hashes in 10 nominal 30 Hz inputs.

The actual experimental QSPI endpoint, CDC FIFO, JPEG core, tile/burst memory and LCD control logic ran in Verilator 5.020 with synthetic instantaneous complete-frame arrivals and a hypothetical one-frame upstream queue. All ten frame IDs were presented; all ten 345,600-pixel framebuffer dumps exactly matched the related C decoder. No modeled underruns occurred. The nine presentation intervals average **29.284 fps**; maximum arrival-to-swap age was **36.067 ms**. This short repeated-source sequence does not prove 30 unique fps, real Wi-Fi/ESP32 throughput, physical FPGA timing, input-to-photon latency, or subjective image quality.

`manifest-10.json`, `verified-10.jsonl`, and `summary-10.json` record input hashes and results. JPEG files and the source video stay local. To regenerate, provide a legally available matching source clip and FFmpeg; `generate.py VIDEO OUTPUT --ffmpeg PATH --frames 10 --start 1` produces the same format. Use the Verilator QSPI binary and C oracle built by [qspi-longrun](../qspi-longrun/README.md), then invoke `check-gameplay.py` with the same arguments as `stream-check-qspi.py`, pointing `--fixtures` at the generated directory, `--work` at a new empty directory, `--frames 10 --strict 0`. Record exact FFmpeg/Pillow versions and input hash; frame hashes verify reproduction. The C oracle shares decoder algorithms with the RTL and is not an independent reference.

A second experiment samples 90 distinct frames at 25 Hz starting 20 seconds into the same clip and replays them at 30 Hz, intentionally accelerating source time by 20%. All 90 presented frame IDs matched all 345,600 corresponding C-model RGB565 pixels, with no modeled underruns. The first-to-last cadence was **30.009 fps over 89 intervals** and maximum arrival-to-swap age was **37.507 ms**. This is roughly three seconds of simulated presentation, not a completed 60-second proof; it omits network and ESP32 behavior. The associated `*-90-accelerated` files preserve all hashes and checks. Across those inputs, C and independent Pillow differed by at most six RGB565 component units, and 99.8085% of components were within one unit; no visual-quality threshold is implied.

As an independent cross-check, Pillow/libjpeg decoded the same ten JPEG inputs and was compared with the related C decoder in RGB565 units using `independent-check.py`. All 10,368,000 individual color components differed by at most one quantized unit (five-bit red/blue, six-bit green); 91.00% of 3,456,000 RGB565 pixels matched exactly. Because RTL matched the C model exactly for these same inputs, this also bounds the observed RTL-vs-Pillow difference for this small sample. `independent-10.json` contains the per-frame histogram. This does not establish a chosen acceptance tolerance or subjective visual quality, and it does not cover other images or codecs.

A third run used 90 distinct frames from the local 1280×720, approximately 29.88 fps precompressed Mass Effect clip `mass-effect-10000.mp4`, sampled and replayed at 30 Hz (source hash and transformations are in `manifest-90-near30.json`). All 90 frame IDs and 31,104,000 framebuffer pixels passed the related C-model comparison with zero detected underruns. Its first-to-last cadence was **30.009 fps over 89 intervals**, with maximum arrival-to-swap age **37.507 ms**. This is a roughly three-second FPGA behavioral simulation with instantaneous complete-frame arrivals and hypothetical external staging; it is not the 60-second acceptance test or real ESP32/Wi-Fi/hardware proof. Against Pillow, 99.7992% of the 93,312,000 RGB565 components were within one quantized unit of the C output; the maximum component difference was 11 units and 45.58% of pixels were exactly equal. These differences are measurements on this sample, not an established tolerance or quality assessment.

A 300-input extension of the same near-30-Hz source completed with 300 ordered presented IDs and exact related-C-model framebuffer comparisons. It measured **29.981 presentations/s over 299 intervals**, maximum modeled arrival-to-swap age **37.507 ms**, and zero detected underruns. There are **299 distinct JPEG hashes among the 300 inputs**: source resampling produced the same image for IDs 94 and 95 (zero-based). Therefore these are not 300 unique visual frames or a unique-frame 30 fps proof. The roughly ten-second run uses instantaneous complete-frame arrivals, an abstract upstream queue and the same functional RTL model, with no ESP32/network or physical timing. Across the 300 JPEGs, 99.8197% of RGB565 components in the independent Pillow comparison were within one quantized unit of the C model, with maximum difference 11; this is a sample measurement, not a prescribed quality tolerance. The `*-300` artifacts contain input and output hashes and full per-frame results.

A separate **strict ten-second** run used 300 distinct JPEGs sampled at 29 Hz from the same approximately 29.88 fps source and replayed at 30 Hz, accelerating source time by about 3.45%. All **300 distinct input hashes** were presented as ordered IDs within the exact 10-second simulated capture window, with 345,600 exact related-C-model pixels per frame and no detected underrun. The wrapper emitted `STREAM_CHECK_PASS` with `strict=1` and exactly 1,000,000,000 cycles at 100 MHz. First-to-last cadence was **29.981 presentations/s** over 299 intervals; arrival-to-swap p50/p95/p99/max was **29.33772 / 36.16168 / 36.85783 / 37.27471 ms**, with **71/300** exceeding 1/30 s age. The `*-300-unique` artifacts preserve manifest, full frame checks, window result and latency analysis. This is a ten-second functional-model milestone, not the separate 60-second acceptance test, native real-time game capture, ESP32/network performance or physical hardware proof.
