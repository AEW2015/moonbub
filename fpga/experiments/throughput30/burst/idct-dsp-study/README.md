# JPEG IDCT intermediate DSP mapping

The existing vendor JPEG decoder already performs multiplications in separate `jpeg_idct_x` and `jpeg_idct_y` transform stages. This isolated experiment asks how Yosys 0.52's generic Xilinx 7-series DSP mapping treats those standalone modules; it does **not** change the decoder or establish acceleration, fit, clock frequency or performance.

Using `synth_xilinx -family xc7 -run begin:coarse; stat` with the default module parameters, the intermediate representations contain **16 DSP48E1 cells for X** and **22 for Y**, respectively. These are standalone synthesis-stage counts, not a routed full-decoder total; later optimization and actual implementation may change them. Each module also produced a warning that `block_out` was replaced by registers. The coarse statistics still contain unmapped generic cells and cannot be used as LUT/register utilization. Source hashes and extracted statistics are included. They are not evidence that the design fits the actual Game Bub device or meets timing.

`run.sh` takes `YOSYS` and `BUILD_DIR` overrides and requires Yosys with Xilinx 7-series mappings. It checks for Yosys's end marker rather than trusting exit status alone. In this environment, an attempted complete Yowasp 0.52 `synth_xilinx` run stopped logging at ABC even though the launcher returned zero, so **no completed LUT mapping or complete synthesis result is claimed**. Proper follow-up is an actual target-part Vivado synthesis and post-route timing/utilization report, then an apples-to-apples fixed-point transform optimization with independent decoder and overflow tests.
