# Combined experimental JPEG X and Y candidates

This behavioral experiment substitutes both isolated [narrow X](../narrow-x/README.md) and [narrow Y coefficients](../narrow-y-coeff/README.md) into an otherwise unchanged experimental QSPI/JPEG/burst-memory/LCD testbench. Both candidate files are copied and renamed only in the temporary build; production sources remain untouched.

On 90 distinct JPEG inputs derived from the near-30-fps local gameplay clip in [gameplay-study](../../gameplay-study/README.md), all 90 framebuffers matched the related C decoder exactly, and the output scoreboard checked **194 full LCD canvas scans covering all 90 frame IDs** without reported mismatch or underrun. Each candidate run's framebuffer hash and presentation cycle exactly matched the corresponding original-X/original-Y run. The model measured 30.009 presentations/s over 89 intervals and maximum arrival-to-swap age 37.507 ms; the schedule assumes instantaneous complete-frame arrivals and an external compressed queue. It is roughly three seconds, not a real network, ESP32 or physical-device performance measurement. `multiframe-simulation.log` and `multiframe-verified.jsonl` contain the checks and source hashes; source video and JPEGs are not redistributed.

Each stage has separately machine-checked compositional sequential-equivalence obligations under its documented reset and default-parameter assumptions. The [IDCT composition audit](../idct-composition-audit/README.md) explains the additional initial-state and first-reset-edge conditions required to infer IDCT-level equivalence because unchanged transpose/FIFO storage is not reset. This test is not unconditional full-decoder equivalence.

Generic intermediate Yosys mapping reported 16→9 DSP48E1 cells for isolated X and 22→14 for isolated Y. These independent coarse counts are not a synthesized combined device, final utilization, clock frequency, speedup, timing closure or fit. Actual Artix-7 implementation and physical validation remain necessary.

Set `FIXTURE_DIR` to a compatible 90-frame manifest and JPEG directory (hashes match `../../gameplay-study/manifest-90-near30.json` for the recorded run), `BUILD_DIR` to a new empty directory, and run `./run-multiframe.sh` with Verilator, Python/Pillow and C++ available. It requires exact C-model frame matches and the multi-frame output PASS marker. The related C decoder is not an independent implementation.
