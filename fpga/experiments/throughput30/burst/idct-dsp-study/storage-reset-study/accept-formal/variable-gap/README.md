# Variable-gap transpose acceptance reachability

The unchanged transpose accepts every offered X beat for this **standalone stream contract**, established by exhaustive finite-state reachability composed with a one-step RTL control equivalence check. It is not a proof that the connected JPEG front end always supplies this contract, or a claim about physical hardware.

The source offers 64 consecutive valid beats with indices 0 through 63, then at least two invalid cycles; at each subsequent idle cycle it may independently start the next block or remain idle indefinitely. Index advances on offered valid, irrespective of accept, as in X. Ready is permanently high; after the initial reset there are no resets or image starts. Input data are irrelevant to transpose control. The initial abstract state `(index, gap, ready_flags, write_bank, read_bank, read_index, FSM) = (0,0,0,0,0,0,0)` represents the state immediately after reset and an idle source. Actual RTL reset clears ready flags, read/write bank pointers, read index and FSM to zero. Source index and gap are part of the reachability state; allowing an initially idle source overapproximates a source that must start immediately.

`reach.py` enumerates all permitted next-input decisions and all reachable states, checks each offered beat for accept, and then independently checks closure of every enumerated state under every permitted next decision. The saved run visits **4,292 states and 4,422 edges**, with no rejected beat and closure checked. Exhausting a finite set closed under the transition relation proves all finite and infinite runs of this contract remain in the set; the initial state is explicitly included. The separate GAP=1 control finds a rejected offer at transition 196; the retained path is the valid/idle decision sequence and matches the earlier SAT witness subject to timestep convention.

`miter.v` independently models the RTL bank flags, pointers, read index, FSM, accept and output-valid control. A Yosys SAT one-step miter starts from arbitrary matched control-state values and arbitrary valid/index inputs, assumes only initial state correspondence, then proves next-state and output equality; it imposes no legal-stream constraints. Transpose output ready is tied high and reset/start low in this step, matching the contract. SAT checks all 6-bit input indices and all 2-bit FSM encodings. An intentionally wrong read-index increment makes the miter fail. The generated RTL copy only adds a control-state observation port; `../cycle-proof/prepare.py` preserves the original logic and source/generated hashes are recorded.

To connect the Python search to that SAT-audited Verilog model, `vectors.py` enumerates every flag, pointer, read-index and FSM value, both valid values, and both classes of index (63 and not 63). `crosscheck.sv` compares all **16,384** one-step transitions from Python against the Verilog model. Only the predicate `idx == 63` affects this control transition, and the SAT miter itself checks every 6-bit index. The reset value and control/output dependency mapping are checked by inspection of the unchanged RTL. Data RAM and read-address state do not feed acceptance, bank control, FSM or read index and are therefore omitted from the reachability abstraction.

```sh
FPGA_DIR=/path/to/moonbub-30fps-study/fpga BUILD_DIR=/tmp/transpose-variable-gap-new ./run.sh
```

The wrapper requires Python 3, Yosys, Verilator and a C++ build toolchain; it writes to a new directory. Saved versions, source hashes, full compressed SAT logs, negative control and concise search/crosscheck logs are in `results/`. The SAT miter and mutation each have a 30-second limit and completed in the saved run. The broader connected IDCT still needs a proof of complete blocks, X indexing, gap behavior across image-start/reset interruptions, and actual upstream protocol/error behavior; this standalone result must not be substituted for that proof.
