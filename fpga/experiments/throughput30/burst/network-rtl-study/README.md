# Packet-trace to QSPI/JPEG RTL experiment

This bounded simulation joins real MSV1 packetization and reference reassembly to the existing experimental Verilator QSPI/JPEG/display pipeline. Ten distinct synthetic 720×480 JPEG fixtures arrive at a nominal 30 Hz; this is not a live gameplay or hardware throughput measurement.

`generate_trace.py` sends each fixture through the actual Python MSV1 packetizer and `Reassembler`, cross-checks each received packet against a host-compiled replay of the unchanged Rust `Receiver`, and records packet arrival times and hashes. Only frames that reassemble completely enter the RTL trace. A one-entry, full-frame queue feeds them to the simulated digital QSPI pins, subject to the credit mechanism. The bench records source ID, capture, network completion, frame commit, and LCD frame presentation timestamps, and accounts for full-frame queue drops. The last stage checks every presented pixel against the C JPEG model using `compare-frame.py --exact`.

The reference-reassembled **whole JPEG** is staged in hypothetical external memory, which is not implemented or sized in this bench. Production Rust instead forwards chunks during reception; no CPU, target firmware, Wi-Fi device, Renode instance or real QSPI peripheral is executing here. The experimental credit endpoint and CDC FIFO are from `cdc-credit/`, not the production FIFO. The JPEG marker guard, burst memory controller and SDRAM model are experimental; the LCD/core and JPEG RTL are included. The C model shares algorithms with the JPEG implementation and is not a fully independent decoder. CRC computation consumes no simulated CPU time. No SDRAM timing signoff or target clock closure is claimed.

## Reproduce

From this directory run `./run.sh`. Requires Verilator 5.x, make, a C++ compiler, host Rust, Python 3 with Pillow, and GNU `timeout`. Set `BUILD_DIR` to a new empty directory to retain generated fixtures, logs, dumps and comparisons; otherwise a temporary directory is created. The wrapper builds the Rust replay and C reference, generates both traces, builds Verilator once, and runs each RTL case with a 400-second wall-time limit. Compilation and comparison are outside that timeout. It never edits production firmware. `results-clean/` and `results-loss/` contain recorded traces, logs and comparison summaries; fixture pixels can be regenerated by the wrapper.

The modeled transport assumes 8 Mbps L3 service and counts 40 bytes of MSV1 plus 28 bytes of IPv4/UDP per packet; it omits MAC/PHY overhead, wireless retries, FEC, audio, contention, host encoding and CPU cost. Independent uniform 0–300 µs packet jitter is assumed. Loss is either none or seeded independent 0.5% per packet, seed 73; these are synthetic assumptions, not measured Wi-Fi. Trace timestamps are integer 100 MHz cycles relative to source capture epoch; RTL records use a warmup offset (2,020,037 cycles here), consistently applied to capture and arrival. Full packet arrival logs, fixture hashes, source IDs, and completion times are in each result directory.

In the loss case, missing datagrams are frame 4 offset 0 and frame 8 offset 23552. The first reference-reassembly rejection for these frames occurs at source-relative cycles 13,551,833 and 29,405,566 respectively; these are packet rejection timestamps, not measured display drops or timeout-expiration times. No complete-frame queue drop occurred. All 18 presented frames matched the C-model output exactly: 345,600 pixels each; no modeled display underruns, RTL core drops or overflows. Frame-by-frame capture, network-complete, commit and presentation cycles are in `rtl.log`; source-relative completion and missing IDs are in `trace-manifest.json`.

The clean trace covers only ten frames; the presentation interval corresponds to about 29.28 fps between first and last modeled LCD boundaries. It does **not** prove sustained 30 fps, radio behavior, input-to-photon latency, or the production system's behavior. Capture-to-present excludes capture, encoding and all omitted transport/software costs. Repeat over longer and representative real network/gameplay traces, implement bounded chunk storage and its error recovery, and measure on the actual ESP32/FPGA before making a system-level claim.
