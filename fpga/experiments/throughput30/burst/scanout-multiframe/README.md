# Multi-frame LCD output and swap check

This isolated Verilator bench extends the experimental QSPI-to-LCD model with a pixel-clock scoreboard and a separate immutable expected-image snapshot for the currently displayed frame. It compares every active 480×720 canvas scanout pixel, in order, to the snapshot, rejects a displayed-ID change within a canvas scan, and requires each of the ten presentation IDs to be completely scanned at least once. Concurrent decoding and writes to the other framebuffer continue. The decoder output and memory for each presented image are also checked against a related fixed-color C JPEG model.

For ten distinct, game-derived 720×480 JPEG inputs from the locally held precompressed Mass Effect clip (`manifest.json` records hashes), Verilator 5.020 checked **21 complete canvas scans and all ten displayed IDs**, with zero detected pixel mismatches, missing IDs, model-reported underruns or framebuffer comparison failures. First-to-last presentation was 29.284 fps over nine intervals. This short experiment does not establish 30 fps, physical scanout timing, real SDRAM integrity, real Wi-Fi/ESP32 operation, display quality or tear freedom under all timings and faults. The associated C model shares JPEG algorithms with the RTL; see the independent Pillow comparison in [gameplay-study](../gameplay-study/README.md). The source video and images are not redistributed.

`run.sh` defaults to generating ten synthetic inputs, or accepts a directory with exactly ten compatible fixtures and manifest via `FIXTURE_DIR`. It requires Verilator, Python/Pillow and a C++ compiler; set `BUILD_DIR` to an empty directory. For the recorded gameplay run, use `gameplay-study/generate.py` with the source hash in `manifest.json`, then supply the resulting directory. The wrapper requires the output-side `MULTIFRAME_SCANOUT_PASS` marker in addition to per-frame C-model checks. Compilation and C-model comparisons are outside the 1,200-second simulation timeout.

The default synthetic-fixture wrapper was also rerun successfully with its separate ten-frame input set; it checked all ten IDs and 21 full output scans. The recorded gameplay results above use the explicit `FIXTURE_DIR` path.
