# Direct simulated LCD output check

The long-run framebuffer scoreboard checks presentation IDs and all memory words but does not directly sample every LCD output pixel. This isolated, one-frame Verilator check extends the same real experimental QSPI/CDC/JPEG/tile/burst/SDRAM/LCD bench with an output-side scoreboard. After the framebuffer swap, it samples RGB565 reconstructed from the LCD RGB output on the pixel clock, requires sequential canvas coordinates for a whole frame, and compares every one of the **345,600** active video pixels to the decoder-pixel scoreboard. The expected framebuffer was independently checked for exact agreement with the related JPEG C model. A missing, out-of-order, or incorrect canvas pixel fails the test.

Verilator 5.020: `SCANOUT_CHECK_PASS pixels=345600`, zero reported LCD underruns, full wrapper exit 0. The single input is a synthetic 720×480 JPEG; the pin-level QSPI, CDC, SDRAM and LCD timing are behavioral digital models. `simulation.log` and `verified.jsonl` preserve the result and fixture hash. This checks scanout values in one model frame; it does not prove multi-frame tear freedom, physical panel timing, target placement, real memory timing, ESP32/Wi-Fi, or sustained frame rate. The framebuffer oracle shares JPEG-decoder algorithms with the RTL, rather than being an independent JPEG implementation.

Run `run.sh` with Verilator, C++, Python and Pillow available. Supply a new empty `BUILD_DIR` if desired. The wrapper regenerates the fixture, builds the bench, checks each C-model pixel, and requires the explicit scanout PASS marker. It does not touch hardware.
